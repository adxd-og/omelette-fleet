# 1.8.0 — Guard v2, the handoff delivered, the review brief: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. In this project the coder never commits: each task's last step is the report, and the session commits after the tester and the review (rules, "Branch per feature").

**Goal:** The guard refuses four more things and records one, through two deliveries (the settings hook and the mod); the handoff gets named fields, a factual stamp and a `prompt.context` delivery; the review brief and the agent templates take the §2c practices.

**Architecture:** One script, `hooks/omelette-guard.mjs`, holds every refusal and record and stays standalone (one dynamic import, `core/ledger.mjs`, as 1.7.3 left it); the mod `mods/omelette-fleet` runs the **rendered** copy of that script through `$.process.run` and answers `{ deny }`, and adds pins, the effort flag, the handoff block and the compaction skip; the templates and the rules file carry the brief. Tasks 1–6 are script rules with rows in `test/hooks.test.mjs`; 7–9 are the mod, tested with `claude plugin test`; 10 is text; 11 docs; 12 the live gate.

**Tech Stack:** Node >= 20, zero runtime dependencies, `node --test`; the Claude Code plugin API (`claude-code` typings written by the engine, 2.1.312 at planning), `claude plugin validate` / `claude plugin test`.

**Spec:** `docs/superpowers/specs/2026-11-03-1.8.0-guard-v2-handoff-review-brief-design.md` — probes P1, P3–P6 answered in it (2026-11-03, Claude Code 2.1.316); P2 is answered at the `/clear` boundary before Task 9 starts (the probe mod `omelette-probe` is written; its files land in the session scratchpad `p2/`).

## Global Constraints

- Node >= 20, no runtime dependency; `npm test` = `node --test test/*.test.mjs`, pristine.
- The guard stays standalone: one dynamic import (`core/ledger.mjs` from `PACKAGE_ROOT`), every other function in the file; a `PreToolUse` refusal is the one non-zero exit (`process.exitCode = 2`, reason on stderr); everything else exits 0, a crash never reaches the harness.
- Guarded roles matched whole: `omelette-coder`, `omelette-coder-medium`, `omelette-tester`, `omelette-reviewer` (`GUARDED_AGENTS`); the refusal names the agent it caught.
- Child processes from the guard: `execFile`, no shell, absolute PATH entries only, `--no-optional-locks` for git, 2 s wall clock each (`GIT_TIMEOUT_MS = 2000`), fail-soft to `unknown`.
- Writes by the guard: O_APPEND | O_NOFOLLOW | O_NONBLOCK on a regular file (`appendToLedgers`' rules), new files through O_EXCL + rename, never through a symlink.
- Headings written into a ledger carry only values matching `^[\w./-]{1,64}$` (the `triggerOf` rule).
- Mod hooks fail open: every gating hook ends `.catch(($, e, next) => next(e))`; the mod reads the rendered script, never the template (`{{marker}}` on line 1); `node` from PATH with `env.PATH` of absolute entries.
- The print's cap stays 12 KB (`HANDOFF_TOTAL_MAX`); the register 6 KB, the backlog 2 KB.
- Never `--dangerously-*`; the CLI never writes a settings file — the snippet is printed, `doctor` reads what was merged.
- The rendered rules file's size test (`test/rules-size.test.mjs`) is raised only with the measured number and the usual comment line.
- Curated files: `.omelette/ledger-*.md`, `.omelette/backlog.md`, `.omelette/decisions.md`, and the file its first line `register: <path>` names, read as `readRegisterPath(projectDir)` reads it.

## Review Focus

1. **A `cd` before the redirection** — `cd .omelette && cat > ledger-x.md` — makes the target's directory unknown: the guard refuses when the command holds a `cd` word and the target's basename matches a curated name (test in Task 3).
2. **A terminator-looking line inside a heredoc body** — `EOF text` or `  EOF` after a plain `<<EOF` — is body, not the end; only `EOF` alone (tabs allowed after `<<-`) ends it (test in Task 1).
3. **A Write whose content is the file re-encoded** — CRLF to LF, trailing newline dropped — is not an append and is refused; the message says "append" so the writer knows what passed (test in Task 3).
4. **A transcript the touched record reads only in part** — a line over 1 MB, a malformed line, a file over 16 MB, two seconds spent — yields a record that says what was skipped; a path outside `~/.claude/projects` yields no record and one stderr line; never a refusal or a crash (test in Task 5).
5. **The mod without a rendered script or without `node` on PATH** passes every call through and says so once; it never denies for a reason that is its own (test in Task 7).
