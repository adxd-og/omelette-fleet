## Global constraints

From the spec, verbatim where it fixes a value:

- `awk` and `sed` leave `NON_EXEC`; "`less`, `more`, `tar`, `cpio` stay in the set".
- The open-group rule "fails closed … the guard does not look ahead for the pipe". Groups: "`(`, `{`, or a compound command (`if`, `while`, `until`, `for`, `case`, a function body)".
- `git config` write words: `--add`, `--replace-all`, `--unset`, `--unset-all`, `--rename-section`, `--remove-section`, `-e`/`--edit`; first positional `set`, `unset`, `rename-section`, `remove-section`, `edit`. Read modes: `--get`, `--get-all`, `--get-regexp`, `--get-urlmatch`, `--get-color`, `--get-colorbool`, `-l`/`--list`; first positional `get`, `list`. Valued options stepped over: `-f`/`--file`, `--blob`, `--type`, `--default`, `--value`, `--url`, `--comment`. "A write word wins over a read mode on the same line."
- `-c` / `--config-env`: refused sections `alias.*`, `include.*`, `includeIf.*`, "case-insensitive"; a key that cannot be read is refused unread; "`-C "$DIR"` is untouched"; "every other key passes", `core.hooksPath`, `core.fsmonitor`, `core.pager`, `core.sshCommand` included.
- `checkout`, `switch`, `restore`, `clean`: the table of spec section 4, cell for cell. "The branch-creation reading of `checkout` and `switch` is unchanged and still decides first." No filesystem read (D2).
- The second refusal sentence names "the role name, what the class is (`discards work in the tree` / `writes git config`), `report instead`".
- Non-goals: no environment route, no plumbing, no `git rm`, no `-c` allowlist; the backlog's other guard and rules tails stay out.
- Version 1.10.1.
- Repository rules: no test reads source text; every refusal test has a neighbour that passes; a time budget is set at ×3 of the local time; no absolute home path in a committed file; the guard is containment, not a security boundary, and every doc line says so.

## Review focus

Input classes no task's tests are sure to cover, each with the task that should:

1. **Bash and zsh disagree on groups.** A `{` is a keyword only at command position and before a blank; a `)` closes a `case` pattern without opening anything; `((…))`, `$(…)`, an array `a=(…)` and a subscript are not groups. A depth counted wrong in the permissive direction hides a body (T1). The binding ruling stands: where the guard cannot read as both shells do, it skips nothing (DECISIONS, hooks/omelette-guard.mjs:525).
2. **The price of T1.** Which everyday commands with git-write text in a heredoc are refused after it and were not before: a function or loop that prints usage text, `( cd d && cat > f <<EOF … )`. The reviewer asks for the list, measured, and it goes to SECURITY's "price of failing closed" (T1, T5).
3. **`git config` across git versions.** `git config get` is a subcommand since git 2.46 and a legacy read of a key `get` before; the reader must be right on both without asking git (T2).
4. **Where a `-c` key sits.** Glued (`-calias.x=y`), detached, quoted whole, a key with a subsection (`includeIf."gitdir:x".path`), no `=` at all, and `--config-env=alias.x=V` glued or detached (T2).
5. **Two readers on one subcommand.** `checkout` and `switch` are asked the branch question first and the tree question second; a cluster (`-qfb x`) answers both (T3).
6. **Linear time.** Group depth is one more thing kept per character; `test/hooks.test.mjs` 2121/2149 hold the time budgets (T1).
7. **The upgrade path.** An install keeps the 1.10.0 guard until `rules --hooks`; the CHANGELOG's upgrade line says so (T5).

## T1 — the heredoc rule (`hard`)

**Who:** `omelette-coder-hard` — bucket `hard`: parser logic in the tokenizer, and the measurement 1.10.0 promised. Then `omelette-tester`, second pass at once.
**Spec:** sections 1 and 2. **Consumes:** `NON_EXEC`, `lineFeeds`, `tokenize`'s `endLine`, `pendingHeredocs`, `skipBodies`, `LEADS_A_COMMAND` (:517). **Produces:** a body read as a command when its line runs `awk` or `sed`, or stands inside a group still open at the line's end.

- [ ] `awk` and `sed` out of `NON_EXEC`; the comment at :445 says why.
- [ ] The tokenizer knows, at each line's end, whether a group is open: `(` … `)`, `{` … `}`, `if` … `fi`, `while`/`until`/`for` … `done`, `case` … `esac`, a function body. `endLine` answers `bodies: true` for a heredoc of such a line. Where a depth cannot be read as both shells read it, the answer is `true`.
- [ ] Tests, in `test/guard-debt.test.mjs`: the four measured awk and sed lines and the three group lines are refused; `sed s/a/b/ <<'EOF'` and each group with a harmless body pass; `cat > f <<'EOF'` with git-write text still passes; a closed group before the heredoc's line (`(true); cat > f <<'EOF'`) passes; the 1 MB budgets hold.
- [ ] Report: `TASK / FINDINGS / DIFF / TEST RESULTS / OPEN QUESTIONS`, with the measured list of everyday commands now refused (Review focus 2), tokens and wall clock.
- [ ] The session reviews, rules, commits.
