# 1.5.0 — the process layer: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cut the guard to the three hooks the measurement kept, take the scout-map mandate out of the rules, and replace the vendor wildcards in every unit's `envPassthrough` with exact names.

**Architecture:** Three independent cuts plus a leftovers task, each on `feat/1.5.0`, each committed by the session once its review passes. T1 removes the auto-handoff estimator from `hooks/omelette-guard.mjs` and shrinks the `handoff` config to one key; `core/rules.mjs` and `doctor` follow. T2 is text: the rules template, ORCHESTRATION, MEASUREMENTS and the tests that pin them. T3 changes what `defineUnit` accepts and what three adapters declare; `core/spawn.mjs` is untouched except for its comment. T4 is escaping and two doc notes. T5 releases.

**Tech Stack:** Node >= 20, ESM, zero dependencies, `node --test`.

**Spec:** `docs/superpowers/specs/2026-09-25-1.5.0-process-layer-design.md` (approved 2026-09-25, a0fb261).

**Planned by:** the session, from the spec and the code at a0fb261 (no scout map; the pointers below were opened by hand on 2026-09-25 after the compaction).

## Global constraints

- `npm test` = `node --test` with no path: it walks the tree, so `.claude/worktrees/` must be empty before a run. Suite at a0fb261: 1175 tests, all pass.
- Never `--dangerously-*` flags; the env allowlist and the scrub stay; the CLI never writes Claude Code's `settings.json` / `.claude.json`.
- The guard's `PreToolUse` refusal logic and classifier are frozen: no edit inside `preToolUse`, `forbidden`, the tokenizer or the write tables (`hooks/omelette-guard.mjs:111-830`).
- Coders never commit. Every behaviour change carries its test in the same commit. Docs are maps: a changed section keeps its map row true.
- Public repo: no personal data, no absolute home paths in committed files. The Astra report (`.omelette/reports/env-allowlist-research-1.5.0.md`) is gitignored; what the adapters cite from it is the vendor guide's relative path (`26-config-reference.md:56`), never a home path.
- Every claim in a coder or tester report is a pointer line (`path:line` · `` `fragment` `` · claim, no backtick inside the fragment); `omelette-fleet check <report>` must pass on it.

## Review focus

Inputs the spec implies and no task's tests exercise unless the lines below are added. Each has its test in the owning task.

1. **An operator's settings.json that still wires the six events** runs the guard on `PostToolUse`, `Stop` and `PostCompact` with a real payload (a transcript path, a `compact_summary`). The guard must exit 0 with nothing on stdout or stderr and leave every ledger byte for byte. (T1)
2. **A `fleet.config.json` carrying `handoff.threshold` / `contextWindow` / `compactSummary`** must warn once per key and render a guard whose literal is `{"enabled":true}`; `set handoff.threshold=85` must be refused naming `enabled` as the one known key. (T1)
3. **`OMELETTE_ENV_PASSTHROUGH=GROK_*`** must still admit a pattern for every unit, while the same pattern in an adapter's `envPassthrough` throws at `defineUnit`. (T3)
4. **A name the wildcard used to admit and 1.4.0 documented as passing** — `GROK_MODELS_BASE_URL` — no longer reaches the child; SECURITY says so. (T3, ledger ruling)
5. **A spooled result whose header field holds `\u001b[2K`**, and a checked report whose fragment or path holds one, print through `results` and `check` as `\u001b`, while the spooled body prints as it was written. (T4)
