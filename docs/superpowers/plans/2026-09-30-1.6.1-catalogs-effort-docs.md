# 1.6.1 Implementation Plan — the catalogs, the effort policy and the docs pass

> **For agentic workers:** one task per coder brief; the session reviews, the clean-context tester runs on every coder result, the session commits.

**Goal:** the Codex catalog knows the GPT-6 generation and the fleet's new default; the tester's effort follows Sonnet 5.5's guidance; ORCHESTRATION and README describe the practice.

**Spec:** `docs/superpowers/specs/2026-09-30-1.6.1-catalogs-effort-docs-design.md`. **Ledger:** `.omelette/ledger-1.6.1.md` (the verified-facts lines of 2026-09-30 are the source of every number below).

**Read:** the spec; `units/codex/models.js` whole; `bin/omelette-fleet.mjs` 409–455 (`probeLogin`) and 2680–2692 (the grok `models` line); `units/grok/models.js` 1–60 (the header style a catalog carries: VERIFIED LIVE lines, dates, vendor vs independent); `test/codex.test.mjs` (the fake `codex` binary pattern); `test/tester-1.6.0-t5b.test.mjs` (how the grok 4.7 catalog task was pinned).

## Global constraints

- Zero runtime dependencies, Node >= 20. Never `--dangerously-*`. The env allowlist, `riskEnv`, the write gates and every tool schema stay as they are.
- Every figure in a catalog string names its source class and date: `vendor` (OpenAI's announcement, 2026-09-22 or 2026-09-29), `AA` (Artificial Analysis, read 2026-09-30), or `probed` (this machine, codex-cli 0.159.2, 2026-09-30). A figure not in the ledger's verified lines does not land.
- No billed call from a coder or a test: the fake `codex` in tests answers `debug models --bundled` from a fixture; the real `codex` is never spawned by the suite.
- Docs are maps, not prose; atomic commits by the session (catalog / doctor line / docs), tests in the same commit as the behaviour.
