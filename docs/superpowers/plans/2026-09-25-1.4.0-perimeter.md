# 1.4.0 — the units' perimeter — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** No Grok run holds a local-read tool and a web tool at once; SECURITY's agy advice says what it allows; `doctor` never writes a control byte it read from project JSON; the Claude-facing prompts lose the nine dated patterns the audit found.

**Architecture:** Four independent tasks on `feat/1.4.0`, each with its tests in the same commit, the session committing after each review. T1 is the only behaviour change a caller can see (`grok_research` reads no local files). T2 is docs. T3 is one helper in the CLI. T4 applies a patch that already exists and passed the suite on a scratch worktree. Nothing new is configurable.

**Tech Stack:** Node >= 20, zero dependencies, `node --test test/`.

**Spec:** `docs/superpowers/specs/2026-09-25-1.4.0-perimeter-design.md` (approved 2026-09-25, "Погнали").

## Global Constraints

- Zero runtime dependencies; Node >= 20; `npm test` pristine at every commit.
- No `--dangerously-*` flag; the env allowlist and the billing scrub are untouched; no write to any settings file.
- `units/gemini/models.js` is a synced copy: never edit it here; edit `~/Desktop/Jaravis/server/gemini/gemini-models.js` and run `npm run sync:catalog` there (T4, step 9).
- Public repo: no personal data, no absolute home paths in committed files.
- Coders never commit; the session commits one task per commit (`git add -p` by file when the tree holds several).
- Bucket rule: T1 → `omelette-coder` (a live probe with an unknown answer decides the empty-toolset form); T2 → a Sonnet docs agent; T3 and T4 → `omelette-coder-medium` (the plan prints the text, the diff and the expected numbers).

## Review Focus

1. `grok_research` called with `cwd` after T1: the argument is still accepted and still sets the working directory, and the answer holds no file contents. Pinned by T1 step 5 (schema) and step 3 (toolset).
2. `webSearch: false` for grok after T1: research runs with no tools rather than with read tools, or refuses with the printed error. Pinned by T1 step 3 (the no-web toolset test) and step 6 (the live probe recorded in the header).
3. Review argv after T1 carries no `--allow` at all, even when `webSearch: true`. Pinned by T1 step 3.
4. A `.mcp.json` whose `command` holds a C1 control (`\u009b`, the 8-bit CSI) or DEL, not only ESC: `visible()` covers `\u0000-\u001f\u007f-\u009f`. Pinned by T3 step 1 (the test plants `\u001b`, `\u009b` and `\u007f`).
5. The rules-size ceiling after T4: the rendered file shrinks, and the `<= 14 030` test stays a ceiling, not a pin. Pinned by the existing `rules-size` test, re-run in T4 step 6.

/**
 * omelette-fleet :: test/grok-profiles.test.mjs
 * 1.4.0 P1: no Grok argv ever holds a local-read tool and a web tool at once.
 */
import { test } from 'node:test';
import assert from 'node:assert/strict';
import { buildArgs, RESEARCH_TOOLS, REVIEW_TOOLS, NO_TOOLS, IMAGE_GEN_TOOLS, IMAGE_EDIT_TOOLS } from '../units/grok/adapter.mjs';

const LOCAL = ['read_file', 'grep', 'list_dir'];
const WEB = ['web_search', 'web_fetch'];
const toolsOf = (argv) => (argv[argv.indexOf('--tools') + 1] || '').split(',').filter(Boolean);
const allows = (argv) => argv.flatMap((x, i) => (x === '--allow' ? [argv[i + 1]] : []));

test('the two profiles are disjoint: research is web-only, review is local-only', () => {
  assert.equal(RESEARCH_TOOLS, 'web_search,web_fetch');
  assert.equal(REVIEW_TOOLS, 'read_file,grep,list_dir');
});

test('no toolset the adapter can pass holds a local-read tool next to a web tool', () => {
  for (const tools of [RESEARCH_TOOLS, REVIEW_TOOLS, NO_TOOLS, IMAGE_GEN_TOOLS, IMAGE_EDIT_TOOLS]) {
    const set = toolsOf(buildArgs({ prompt: 'p', tools, maxTurns: 30 }));
    const local = set.some((t) => LOCAL.includes(t));
    const web = set.some((t) => WEB.includes(t));
    assert.ok(!(local && web), `${JSON.stringify(tools)} holds both local and web tools`);
  }
});

test('the web allow rules ride on the research profile only', () => {
  assert.deepEqual(allows(buildArgs({ prompt: 'p', tools: RESEARCH_TOOLS, maxTurns: 30 })), ['WebFetch', 'WebSearch']);
  assert.deepEqual(allows(buildArgs({ prompt: 'p', tools: REVIEW_TOOLS, maxTurns: 30 })), []);
  assert.deepEqual(allows(buildArgs({ prompt: 'p', tools: NO_TOOLS, maxTurns: 30 })), []);
});

test('research and review both stream NDJSON, whatever their toolset', () => {
  for (const tools of [RESEARCH_TOOLS, REVIEW_TOOLS, NO_TOOLS]) {
    const a = buildArgs({ prompt: 'p', tools, maxTurns: 30 });
    assert.equal(a[a.indexOf('--output-format') + 1], 'streaming-messages-json', JSON.stringify(tools));
    assert.ok(a.includes('--include-partial-messages'));
  }
});
