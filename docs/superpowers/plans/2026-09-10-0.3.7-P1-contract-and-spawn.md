# 0.3.7 · P1 — the contract that costs nothing where the rules already are, and a tail buffer that is a queue

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. Steps use `- [ ]`. **Coder sub-agents never commit** — the last step of every task is a report to the orchestrating session, which reviews and commits on `feat/0.3.7`.

**Goal:** M1 and M2 of the 0.3.7 spec. A unit server that starts in a project already carrying `.claude/rules/omelette-fleet.md` sends **one line** at `initialize` instead of the ~300-token fleet contract, because that file states everything the contract states and more; a top-level `contract: auto | full | short` key decides it outright when an operator would rather not be detected; `doctor` prints which one this project gets, `show` lists the key and `set contract=short` writes it (M1). And `runProcess`'s stdout tail stops being a string that is re-flattened and re-copied on every chunk: chunks go into an array with a running total, the head is dropped while the rest still covers the cap, and the array is joined once at close (M2). Then the docs for both, and the `## 0.3.7 — unreleased` CHANGELOG heading P2–P4 append to.

**Architecture:** M1 is one new function in `core/rules.mjs` — `contractFor({ cwd, env, mode })` — plus the constant it can return, the config key it reads and three readers: `unitInstructions`, which every unit server already goes through; `startUnit`, which resolves it once at server start (Claude Code starts an MCP server in the session's project directory, so `process.cwd()` *is* the project); and `cmdDoctor`, which prints the same answer for the directory it was run in. The detection is the marker test that already exists (`parseRulesMarker`) against the path that already exists (`rulesTarget`), so nothing new decides what "our rules file" means. `show`/`set` grow the first **top-level scalar** block the CLI has had, driven by `SETTINGS_SCHEMA` exactly as the `agents` and `handoff` blocks are driven by theirs. M2 is internal to `core/spawn.mjs`: the `data` handler and the `close` handler, nothing else — same `stdout`, same `capped`, same `stderr`, for every caller.

**Tech Stack:** Node ≥ 20, zero runtime dependencies (`node:` builtins only), plain ESM, `node --test test/` with fake vendor binaries under `test/`.

**Spec:** `docs/superpowers/specs/2026-09-10-0.3.7-design.md` — **M1 and M2 are this package, in full.** M3 (P2), M4 (P3), M5 and M6 (P4) are not touched here.

**Master plan:** `docs/superpowers/plans/2026-09-10-0.3.7-master.md`. Its "Shared interfaces" are binding, verbatim:

  ```js
      // 64 KiB chunks under a 4 MB cap moved about 3 GB of string through the
      // heap to keep 4 MB of it. One chunk above the cap is still held — a chunk
      // has to be held to be measured — and that transient is all that is left.
      const chunks = [];
      let total = 0;
      let dropped = false;
      // `slice(-0)` keeps the WHOLE string, so a cap of 0 has always meant "no
      // tail kept back, but say it was capped". Dropping under it would silently
      // change that for a caller nobody has audited, so the queue only drops
      // while there is a cap to drop against.
      const capping = outputCap > 0;
      let errBuf = '';
      let capped = false;
      child.stdout.setEncoding('utf8');
      child.stdout.on('data', (c) => {
        chunks.push(c);
        total += c.length;
        while (capping && chunks.length > 1 && total - chunks[0].length >= outputCap) {
          total -= chunks.shift().length;
          dropped = true;
        }
      });
  ```

**Type consistency across tasks.**
- `contractFor({ cwd?: string, env?: object, mode?: string }) → { text: string, short: boolean, reason: string }` is total: it never throws (`marked()` swallows every filesystem error, `fleetSettings` never throws by contract) and always returns all three keys. `text` is `FLEET_CONTRACT` or `SHORT_CONTRACT` and never a computed string, so `short === (text === SHORT_CONTRACT)` holds by construction. Matches the master's shared interface exactly.
- `unitInstructions(unit, o = {})` — `o` is `contractFor`'s options object, forwarded whole and never inspected, so the two signatures cannot drift. The one-argument call is still legal and now means "for this process's cwd and env"; `test/rules-tester.test.mjs` uses the `{ mode: 'full' }` form, `core/unit.mjs` the `{ cwd, env }` form.
- `SETTINGS_SCHEMA.contract` is an ordinary `coerce` spec of type `enum` — the same shape `HANDOFF_SCHEMA.threshold` and `KEY_SCHEMA.cancel` have — so `describeSpec` renders it (`auto | full | short`) and `coerce` validates it with no new case in either. `fleetSettings().contract` is therefore always one of the three literals, which is why `contractFor` can test it with two `===`.
- `fleetSettings(env) → { updateCheck: boolean, contract: string, sources: Record<string,'default'|'file'>, warnings: string[], configPath: string }`. `sources` has exactly the keys of `SETTINGS_SCHEMA`, so `fleetRows` (T5) can index it without a guard, and P3/P4 adding a key to that schema adds a row to `show fleet` and a `set` target with no further edit.
- `cmdSet`'s four assignment arrays are disjoint by construction (each branch `continue`s), and `fleetAssignments` entries are `{ key: string, value: boolean|string }` — the same `{key, value}` shape as `handoffAssignments`, so the report loop and the merge loop read alike. The merge writes `next[a.key]`, a top-level scalar, which is why it needs no `shape.push` entry: there is no object to refuse to replace.
- `runProcess`'s resolved value keeps every key and every type: `{ stdout: string, stderr: string, code: number|null, signal: string|null, killed: boolean, capped: boolean, cancelled: boolean }`. Inside, `chunks: string[]` (`setEncoding('utf8')` means whole characters — a multi-byte character split across a read is reassembled by the stream's decoder, so `total` counts characters exactly as the old `next.length` did), `total: number`, `dropped: boolean`, `capping: boolean`. `out` moves from an outer `let` to a `const` inside the `close` handler; nothing else references it — the `error` handler rejects and the `resolve` is in the same scope.
- The `contract` doctor line is built from `contractFor`'s return and nothing else, so `doctor`, a unit server's `up ·` line and `unitInstructions` cannot describe one machine differently: all three call the same function with `{ cwd, env }` from their own process.
