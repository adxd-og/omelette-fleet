## Goal

A fifth Gemini tool, `gemini_test`, behind `OMELETTE_ALLOW_REPRO`, macOS only: a HEAD clone of the work tree with the coder's patch applied and committed, the named dependency directories copied in by `cp -c`, agy run whole under a rendered kernel profile (A) with a scratch home, Neon writing tests with its file tools only; after each round the unit runs one fixed test command under Mistral's no-network profile (B) and hands the output back, for at most `rounds` rounds inside one budget; the answer carries the unit's own round lines, Neon's last message, the files changed outside the test directories and the unit's diff under `## proposed tests (not applied)`. Release 1.13.0.

## Architecture

The generic pieces of `units/mistral/repro.mjs` move to two core modules — `core/clone.mjs` (runs root, HEAD clone, `assertRun`, the diff, removal, the model-text neutraliser) and `core/seatbelt.mjs` (`sandbox-exec`, `regexLiteral`, `nodeUp`/`nodeReach`/`nodeEnv`) — and `repro.mjs` re-exports them under its own names and messages, so Mistral and its tests do not change (T4). Core gains three small options: `runProcess({ outFd })`, `ctx.spawn({ wrap })` and a tool's `modelKey` (T1–T3). The Gemini side is three files: `units/gemini/agy.mjs` (agy's JSON envelope and quota patterns, moved out of the adapter so both tools' code can share them), `units/gemini/test-run.mjs` (the run directory, the patch, the deps, the program and its toolchain reach, profile A's renderer, profile B's argv, the test-command runner, the cleanup) and `units/gemini/test.mjs` (the preamble, one round, the loop, the answer, `runGeminiTest`); `units/gemini/adapter.mjs` registers the tool and its five config keys. Both spawns go through `ctx.spawn`, so the env allowlist, the billing scrub, the cancel signal and the live-group kill hold for both; `wrap` puts `/usr/bin/sandbox-exec` in front. Profile B is `units/mistral/repro.sb`, byte for byte, read in place (spec: «with the same profile»), unless T7's probe says otherwise.

**Tech stack:** Node ≥ 20, zero runtime dependencies, ESM `.mjs`, `node --test`; macOS `sandbox-exec`; agy 1.5.16 (live steps only — every test fakes agy).

**Spec:** `docs/superpowers/specs/2026-11-23-neon-tester-design.md` at `9ccd1b4` (approved 2026-11-24). Branch `feat/neon-tester`, ledger `.omelette/ledger-neon-tester.md`, BASE `9ccd1b4`.

## Global constraints

From the spec, verbatim where it fixes a value:

- `gemini_test`, on the Gemini unit, beside `gemini_research`. Closed by default.
- `cwd`: "Absolute path of the work tree. The copy is a HEAD-only clone of it …; uncommitted and ignored files are not in it."
- `patch`: "Absolute path of a patch file the session wrote: the coder's change as `git diff HEAD` after `git add -N` of new files … The unit applies it in the clone (with the clone's git config isolated, as Mistral's `CLONE_CONFIG`) and commits it there … A patch that does not apply is an error before any spawn."
- `prompt`: "The unit adds its own preamble: write tests with your file tools only, run no command, the unit runs the test command after you finish and gives you its output."
- `testCommand`: "an argv array (no shell string, no shell)"; its first word "is either a name on the config list `gemini.testPrograms` (default `node`, `npm`, `npx`, `pnpm`, `yarn`, `python3` …), resolved to an absolute path outside the copy, or a relative path that lies under one of the call's `deps` entries … Either way it is a file Neon cannot write."
- `deps`: "paths relative to `cwd` … Each must be a directory inside the work tree that git ignores whole, and none may be or contain `.git` or `.omelette` — a slip like `"."` is an error before any spawn. The unit copies each into the copy at the same place (on APFS a copy-on-write clone, `cp -c`) … before round 1. Nothing else of the work tree enters the copy."
- `rounds`: "Default 3, at most 5." `model`: "default the config key `gemini.testModel`, default `Gemini 4 Neon (High)` — separate from `gemini.model`, which stays Hydrogen (High)".
- The answer, in order: "one line per round with the test command's exit code and wall time, measured by the unit; Neon's last message; under the unit's own heading `## proposed tests (not applied)`, the diff … taken by the unit outside both profiles against a fresh copy of the clone's `.git` kept in the run's out dir (Mistral's `cloneDiff`, with its protections …, 1 MB cap, a model-written heading of that name is marked). A file Neon changed outside the test directories is listed by name above the diff."
- "A call is never retried … The result is spooled like every unit call (`gemini_result`)."
- The run: "Under `<OS temp>/omelette-gemini-test/run-*`, 0700, the operator's: `clone/`, `tmp/`, `home/` (… an empty directory with `Library/Keychains` linked to the real one), `out/` … Removed after the call, unless `gemini.testKeep` (default `false`)."
- Profile A: "writes only the run's `clone/`, `tmp/` and `home/`, `/dev/null`, the command's own `/dev/tty` and the fd devices — and not the copied `deps` directories inside `clone/`"; "reads of the operator's home denied whole, re-allowed: `~/Library/Keychains` (read only) and whatever agy's sign-in needs …, agy's binary and the directories its real path lies in"; "the work tree (`SRC`), the fleet home, other runs and the fleet's other `omelette-*` temp dirs denied, the run's own dirs re-allowed last"; "no hand-off to a process outside the profile … as `repro.sb`"; "the network open".
- agy's flags, every round: "`-p`, `--output-format json`, `--print-timeout`, `--model`, `--disable-slash-commands`, `--mode accept-edits`, `--settings` with `allowNonWorkspaceAccess: false` and a `permissions` object the unit pins — no `command` rule at all"; "Never `--sandbox`, `--dangerously-skip-permissions`, `--mode auto`, `--continue`."
- Profile B: "no network, writes only `clone/` and `tmp/`, no read of the home but the adapter's node (`NODE`, `NODEUP`), `HOME` set to `tmp/`, the process group killed at the end (`killGroupOnExit`), a time limit per run (`gemini.testRunTimeoutS`, default 300)"; "`SRC` stays denied whole"; output "to `out/`, … cut to their last 16 KB for the model, and … made safe to show (control characters stripped …)".
- The gate: "`OMELETTE_ALLOW_REPRO` … opens `gemini_test` too … `OMELETTE_ALLOW_WRITE` opens nothing here … Closed, the tool answers with an error naming the variable. macOS only." "No session sets the variable for a command of its own."
- "The env allowlist and the billing-key scrub apply to both spawns. `gemini_research`, `gemini_deep_research` and `gemini_image` do not change. The unit's intent gate (`mutateGate`) is not put on `gemini_test`."
- The loop: "Round k > 1: the unit resumes the same conversation (`--conversation <id>`, the id from round 1's JSON …) with the test command's output. The loop ends when Neon answers `DONE`, when `rounds` is reached, or when a round ends with no output (…that round's diff still counts)."
- "The rounds are for tests that run, not for green … The preamble of every round says so … an assertion is never weakened to match the code. `DONE` means «the tests run and test what the brief asks», whatever their result." The answer carries "the exit code, the wall time and the last 40 lines of the test command's output, and the run's `out/` keeps each round's diff when `testKeep` is on."
- "`gemini.testTimeoutS`, default 1500 s: the unit starts no round once it is spent, ends a round that outlives it, and takes the diff of what is there." "`doctor` prints the worst case against that limit, as it does for deep research."
- Release 1.13.0; docs SECURITY, ADAPTERS, CONFIG, ORCHESTRATION («not yet in the tester flow»), MEASUREMENTS, CHANGELOG; the rules file's tester flow and the agent definitions do not change in this plan.
- Project rules: a probe or test runs no real-shell loop and gives every child a timeout (5 s for a probe; a test's wall-clock budget is at most ten times the local time); no personal data and no absolute home path in a committed file; never a `--dangerously-*` flag; the env allowlist and billing scrub on every spawn; the CLI never writes Claude Code's settings; every behaviour change gets a test; managed files under `.claude/` are rendered, not edited; a test stays only if it pins a spec line nothing else pins, kills a mutant no other test kills, or pins a found defect; no test reads source text or documentation prose; no test needs the real agy or the network.
