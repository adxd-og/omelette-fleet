# Evals MVP: implementation plan

**Spec:** `docs/superpowers/specs/2026-10-16-evals-mvp-design.md` (approved 2026-10-16). Read it whole.
**Read for this plan:** the spec; `core/client.mjs` (`callUnitServer`, the path `omelette-fleet call` uses); `bin/omelette-fleet.mjs` `cmdCall` (~line 3230) and the `results --stats` code (what it reads to get per-call usage); `~/.omelette/fleet-log.ndjson`, its shape only (one line per unit call); `units/*/models.js` (model and effort ids); `package.json` `files`.

## Global constraints

- **Zero runtime dependencies, Node ≥ 20, plain ESM `.mjs`.** No chart library, so the SVG is written by hand.
- **The scripts hold no task text, no key and no answer.** They read and write only the private directory: `--dir`, default `<repo>/.omelette/evals`. Every file under it stays out of git (`.omelette/` is ignored).
- **Public output is `evals/README.md` and `evals/charts/*.svg` only.** Neither enters the npm package: check `package.json` `files`, and add an exclusion if a glob would catch them.
- **Units are called through the real path** (`callUnitServer` on `servers/<unit>.mjs`), so the fleet's guards, sandboxes, timeouts and config apply. Never spawn `agy`, `grok` or `codex` directly.
- **A failed call is recorded as failed.** No silent retry.
- **No absolute home paths or personal data** in anything committed.
- **Test discipline:** tests pin behaviour (blinding, aggregation, the chart's numbers, the leak check), never source text.
- **Do not commit.** The session commits each task after review.

## Task 1: `scripts/eval-run.mjs`

`node scripts/eval-run.mjs --suite R|V --arm <unit>:<model>[:<effort>] [--runs N] [--batch] [--dir D] [--snapshot PATH]`

1. **Read the suite.** It reads `<D>/suites/<suite>/tasks.jsonl`.
2. **Build each call.**
   - **R, Gemini** → `gemini_research`; R, Grok → `grok_research`; R, Codex → `codex_research`. One call per question; with `--batch`, one call holding every question, numbered, with the answer asked for per number. `--batch` is for Argon.
   - **V, Codex and Grok** → `codex_code_review` / `grok_code_review`, with `cwd` = `--snapshot`. The snapshot is an extracted `git archive` of the task's `commit`, made by the script into the private dir when absent; it has no `.git`.
   - **V, Gemini** → `gemini_research`, with the file's text from the snapshot appended to the brief.
   - **Model and effort.** Pass `model` (and `effort` where the unit takes it: Codex and Grok); for Gemini the effort is part of the model id. Codex with no effort gets its pairing (xhigh).
3. **Write one line per call** to `<D>/runs/<YYYY-MM-DD>/<suite>-<arm>.jsonl`, with these fields:
   - `taskIds`, `arm`, `unit`, `model`, `effort`, `run`;
   - `cli`: the vendor CLI's `--version`, read once per arm;
   - `startedAt`, `wallMs`;
   - `ok`, `answer` (the tool's text), `error`;
   - `usage`: what the unit reported for that call — find where `results --stats` gets it (the fleet log or the result spool) and read the same record for this call; `null` when the unit reported none.
4. **Arms run sequentially**, calls one at a time. `--dry-run` prints the plan of calls and makes none.

**Tests** (fake unit servers, as `test/*.test.mjs` already do with fake binaries):
- the call plan for each suite and unit (tool, arguments, batch vs per-question);
- a failed call recorded with `ok:false` and no retry;
- the snapshot has no `.git`;
- the output line's fields.

## Task 2: `scripts/eval-blind.mjs` and grading support

`node scripts/eval-blind.mjs --date YYYY-MM-DD [--dir D]`

1. **Blind the answers.**
   - Read every run line of that date.
   - Strip model names and ids, tool names, CLI versions and timings from each answer. The text is redacted by a list of strings built from the unit catalogs (`units/*/models.js` ids and labels, plus `Gemini`, `Grok`, `Codex`, `GPT`, `Argon`, `Flash`, `Sol`, `Astra`), each replaced with `[model]`.
   - Shuffle with a seed printed in the output.
   - Give each answer a blind id.
2. **Write two files:**
   - `<D>/grading/<date>/blinded.jsonl`: blind id, suite, task ids, redacted answer;
   - `<D>/grading/<date>/mapping.json`: blind id → arm and run.

   The grader is given only `blinded.jsonl` and the key, never the mapping.
3. **Rubric file.** Write `<D>/grading/<date>/rubric.md` for the grader, from the spec's Grading section:
   - **R**, per task: correct / partly / wrong / no-answer; per cited URL: supports / real-not-supporting / unreachable-or-invented.
   - **V**, per key item: found / not; per finding not in the key: plausible-new / false.
   - The output line format for `grades.jsonl`.
4. **`--aggregate`** joins `grades.jsonl` with the mapping into `<D>/aggregates/<date>.json`, per arm:
   - R: correct, partly, wrong, no-answer; invented URLs; the trap passed or failed;
   - V: recall (key items found / 7), precision (key + verified-new over all findings), false findings;
   - mean `wallMs`, mean token usage;
   - per-run values kept beside the means.

   Grades that the session overturned (`overturned: {from, to}` in a grade line) count by their final value, and the aggregate reports the overturn count.

**Tests:**
- redaction removes every catalog id and label from a sample answer;
- the mapping round-trips;
- the aggregate's numbers on a fixed grades fixture;
- an overturned grade counts by its final value.

## Task 3: `scripts/eval-chart.mjs`, `evals/README.md` and the leak check

`node scripts/eval-chart.mjs --date YYYY-MM-DD [--dir D]` writes `evals/charts/<chart>.svg` from the aggregate:

1. **Four charts**, as the spec's Charts section describes:
   - `r-accuracy.svg`: correct per arm, a bar for the mean and a dot per run; invented URLs as a second series;
   - `v-recall-precision.svg`;
   - `effort.svg`: Argon and Flash, R and V against Low, Medium and High;
   - `cost.svg`: score against mean wall time, one point per arm; a second panel for tokens where reported.
2. **Each chart's caption** gives the date, the CLI versions and N. With N ≤ 2 it says "runs shown, no intervals". The Argon R batch is marked "one prompt for all questions".
3. **Readable in GitHub's light and dark themes:**
   - no hard-coded white background;
   - text and lines in a colour that holds on both (a `<style>` with `@media (prefers-color-scheme: dark)` inside the SVG);
   - every element labelled, with `<title>` and `<desc>` for screen readers.
4. **`evals/README.md`:**
   - a map: what is measured, the method in one screen, the charts embedded;
   - why the tasks and keys are not published;
   - how to re-run, in commands, with no task text.
5. **The leak check, `test/evals-leak.test.mjs`.**
   - When `.omelette/evals/suites/*/tasks.jsonl` or `key.jsonl` exist: no line of the prompts, answers or key defects (any string field ≥ 24 characters) appears in any file under `evals/` or `scripts/eval-*`.
   - When they do not exist (CI): the test skips, saying why.
   - It also pins that `package.json` `files` does not ship `evals/`.

**Tests for the charts:** the chart generator, given a fixed aggregate, writes SVG whose bar heights and labels match the numbers. Parse the SVG text for the numbers; do not snapshot whole files.

## Review focus

1. A redaction that misses a model name in an answer: for example "As Gemini 4 Argon, I…", or a model name inside a URL.
2. The fleet log or result spool attributing usage to the wrong call when two calls finish close together.
3. A key or prompt string reaching `evals/`, for example through a chart's `<desc>`.
4. The V snapshot keeping `.git`, or `cwd` pointing at the live checkout.
5. An arm whose effort silently fell back: the run line must record the effort actually used, as the unit reports it.
