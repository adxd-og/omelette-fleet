# 0.3.4 · P3 — the spool always names a model; the progress-token note; an unreadable settings file is named

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development (or superpowers:executing-plans). Steps use `- [ ]`. **Coder sub-agents never commit** — the last step of every task is a report to the orchestrating session, which reviews and commits on `feat/0.3.4`.

**Goal:** Close the three one-line backlog items of 0.3.4. (3a) A spooled result is never filed under an empty `model:` — the adapter reports the id it pinned itself, and a unit that leaves the choice to its CLI is filed under the literal `(vendor default)`. (3b) `docs/CONFIG.md` says why the idle wall is not the threat it looks like on Claude Code ≥ 2.1.263. (3c) A settings file that exists and does not parse is **named** by `doctor` instead of being skipped in silence, once per file however many of doctor's readers opened it.

**Architecture:** Three independent seams, no new module.
- `core/unit.mjs` grows one report channel on the tool ctx — `usedModel(id)` — and one line of resolution inside `finish()`: `model:` is the explicit/configured model, else the adapter's report, else `VENDOR_DEFAULT_MODEL`. Nothing else in the runtime moves: `ctx.model` keeps its current value, `core/status.mjs` keeps schema 1, `core/results.mjs` is not touched at all (its `renderResult` already prints whatever string the record carries).
- `units/codex/adapter.mjs` calls `ctx.usedModel(model)` in `runOnce`, the single funnel all three codex tools spawn through. `units/grok/adapter.mjs` and `units/gemini/adapter.mjs` are deliberately **unchanged** — they pass `ctx.model` straight to their CLI and never learn what the CLI chose.
- `bin/omelette-fleet.mjs`: `readClientEnv` returns `unreadable: string[]` beside its value, `idleWall`/`timeoutWalls` carry it up, `hookWiringAt` adds `unreadablePaths` beside the short names it already reports, and `cmdDoctor` merges the two lists and prints one line per distinct path.
- `docs/CONFIG.md` gains three sentences; `CHANGELOG.md` gains the 0.3.4 bullets for this package.

**Tech Stack:** Node ≥ 20, zero runtime dependencies (`node:` builtins only), plain ESM, `node --test` with the fake vendor binaries already under `test/`.

**Spec:** `docs/superpowers/specs/2026-09-08-0.3.4-design.md` — **§3a, §3b and §3c are this package.** Nothing else in that document belongs here.

**Master plan:** `docs/superpowers/plans/2026-09-08-0.3.4-master.md`. Its "Shared interfaces" block is binding:
- `bin/omelette-fleet.mjs`: `readClientEnv(name, opts) → { value, source, unreadable: string[] }`.
- `core/unit.mjs`: tool ctx gains `usedModel(id)`; `finish()` spools `model:` = explicit/configured model → `usedModel` report → `'(vendor default)'`.
- Doctor prints P1's `handoff:` line and P3's `settings: <path> unreadable` line in the per-project block, **handoff line first**.

   *
   * @returns {{value: string|null, source: string|null, unreadable: string[]}}
   *   `source` is 'process env' or the absolute path of the file the value came
   *   from; `unreadable` holds absolute paths.
   */
  function readClientEnv(name, { cwd = process.cwd(), env = process.env } = {}) {
    if (env[name] !== undefined && String(env[name]) !== '') return { value: String(env[name]), source: 'process env', unreadable: [] };

      ...settingsTargets({ global: false, cwd, env }).slice().reverse(),
      ...settingsTargets({ global: true, cwd, env }).slice().reverse(),

    for (const { path } of files) {
      let text;
      // ENOENT is the normal case. Anything else — a directory at that name, a
      // file this user cannot open — means the contents are there and lost.
      try { text = readFileSync(path, 'utf8'); } catch (e) { if (!e || e.code !== 'ENOENT') unreadable.push(path); continue; }
      let parsed = null;
      try { parsed = JSON.parse(text); } catch { parsed = null; }
      if (!isObj(parsed)) { unreadable.push(path); continue; }
      if (!isObj(parsed.env)) continue; // readable, and says nothing about this variable
      const raw = parsed.env[name];
      if (raw === undefined || raw === null) continue;
      if (!['string', 'number', 'boolean'].includes(typeof raw)) continue;
      return { value: String(raw), source: path, unreadable };
    }
    return { value: null, source: null, unreadable };

**Spec ambiguities, and how they were resolved**

1. **"ignored for `local` tools" — absent, or present and inert?** Resolved as **present and inert** (a no-op function on the reduced ctx). The word is "ignored", not "absent"; an absent function would turn a shared adapter helper into a `TypeError` that the local branch converts into an error answer; and a no-op costs one updated assertion in the test that pins the reduced ctx's exact key list. That assertion is edited in T1 step 1 with the reason in a comment.
2. **Does the *record* carry `(vendor default)`, or only the rendered header?** Resolved as **the record**. The spec says "`finish()` spools `model:` as …", and both readers (`<unit>_result`, `omelette-fleet results`) re-render the parsed header, so a value invented at render time could not reach them. This also means the `onResult` seam sees the resolved string — additive, since P1/P2's tests assert `Object.keys(record)`, not `record.model`.
3. **A refusal before the spawn now spools `model: (vendor default)`** where it used to spool an empty line (unknown-model refusal excepted: that one has an explicit model). Accepted: it is the model the run *would* have used, it is the same phrase `startUnit` already prints for an unconfigured unit, and the alternative — a special case for refusals — would make the header mean two different things.
4. **`usedModel` is not validated against the catalog.** Deliberate: an adapter reports what it handed the CLI, and a catalog that has drifted behind the vendor must not turn a true report into a silent `(vendor default)`. Pinned by the `m-unlisted-9` assertion.
5. **`gemini_deep_research` also pins models the runtime did not choose** (`stageModels` picks a balanced-tier Medium/High pair when nothing is explicit — `units/gemini/adapter.mjs`, `stageModels`). Spec §3a names Codex only and says gemini "trusts its CLI default", which is true of `gemini_research` and false of the deep-research pipeline. **Resolved: out of scope for P3, deliberately** — one call uses two different ids across three stages, so a single `model:` string would misreport rather than inform, and inventing a multi-model header shape is a spec change, not a one-line item. Flagged to the orchestrator in T2 step 5 for the 0.3.5 backlog.
6. **Where the `settings:` line sits and what it looks like.** The spec and the master both quote the line as `settings: <path> unreadable — …`, i.e. a `key: value` line, which in this doctor's layout is a **continuation line** of the project block (14-space indent), exactly like `wall-clock:`, `raise it:`, `idle:`, `deep research:` and P1's `handoff:`. Resolved that way rather than as a `settings` label column, which would have dropped the literal string the spec quotes. Consequence, noted for the implementer: when no unit is enabled the timeout block is absent and the settings lines print directly under `hooks` — still self-describing, and covered by the second test.
7. **"merged … so a file is named once" — union, or suppress what the hooks line already mentions?** Resolved as **union with dedup by absolute path**. The hooks line only mentions unreadable files while the wiring is incomplete, so suppression would make the `settings:` line disappear exactly when a fully-wired machine has a broken file; and the master's wording is "merged with the paths `hookWiringAt` already reports".
8. **`readClientEnv` stops at the first hit, so it cannot see a broken file *after* the winner.** Left as is: rescanning would change no value and cost reads, the files it does open are precisely the ones whose contents were lost, and `hookWiringAt` always opens all four so the merged list is complete either way. Documented in the function's doc block and pinned by the "no wall to report" test.
9. **`hookWiringAt` still treats a non-ENOENT read error as absence** (`try { raw = readFileSync(path) } catch { continue }`), where `readClientEnv` now names it. Not changed: P3's scope is `readClientEnv`, and widening the hooks reader would change the `hooks` line's reason text for an EACCES file — a behaviour change with its own test that nobody asked for. Noted here so a reviewer does not read it as an oversight.
10. **`CHANGELOG.md` is not in the master's P3 "Touches" column.** Added anyway (T4 step 4): the release checklist requires the 0.3.4 entry, and writing it beside the change is cheaper and more accurate than reconstructing it at release time. If P1 already wrote a bullet covering one of these items, merge rather than duplicate.
