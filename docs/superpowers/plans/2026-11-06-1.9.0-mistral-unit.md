## Review Focus

1. **A model that writes outside the clone through an in-process tool.** `edit`/`write_file` are off by default, but `reproTools` lets the operator name them: they are Vibe's in-process tools, which the Seatbelt under `bash` never sees — Vibe's `outside_workdir = "deny"` and the clone as `--workdir` are the only belt they have, and the operator who names them takes that (the spec's own ruling, §3). The adapter keeps both in place whatever `reproTools` says (test in Task 3: `reproTools=bash,read_file,grep,edit` → argv carries `--enabled-tools edit`, the clone is still the workdir, the home's `outside_workdir` is still `deny`).
2. **A `cwd` that is not a git work tree, or is one with a dirty tree.** Repro refuses the first naming `git rev-parse`; for the second it clones HEAD and the answer's first line says uncommitted changes were not in the clone (tests in Task 3).
3. **A run that Vibe stops on `--max-price` or `--max-turns`.** Not a deadline: `outcome` is not `deadline` and the exit is 3 — the answer is returned marked with the `exited` kind and the `outcome` word in the log, never retried (test in Task 2: export `outcome: "max_price"`, exit 3 → `partial: true`, marker `CLI exited 3`).
4. **A home rendered by an older catalog.** `models.js` changed, the home on disk still lists the old aliases: the run would hit Vibe's silent fallback. `ensureHome` re-renders when the rendered bytes differ, before every spawn, and the fallback refusal catches what slips (tests in Task 1 and Task 2).
5. **A login-env probe answered by the operator's login shell.** If Vibe ever runs the probe outside `tools.bash.shell`, the model's shell sees `.zshrc` exports. The wrapper test (Task 1) pins the interception; the live gate (Task 6) runs the model's `bash` with `env` and the session reads the answer for a planted `OMELETTE_PROBE_SECRET` exported in a throwaway `.zshrc`.
