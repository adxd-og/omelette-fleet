# 1.7.0 Implementation Plan — the fleet pane

> **For agentic workers:** one task per coder brief; the session reviews, the clean-context tester runs on every coder result in two passes, the session commits.

**Goal:** a Claude Code mod, shipped in this package, that draws the orchestrator, its sub-agents and the three units as a graph with live links, a history of who called whom, and the session's usage — and changes nothing it observes.

**Architecture:** every decision about what is on screen is a pure function in a `.mjs` file under `mods/omelette-fleet/hooks/`, tested by `npm test` on Node 20 and 22 with no Claude Code. One thin hooks module (`register.tsx`) turns engine events into model events, keeps the model in `$.state`, and maps layout rows to elements. The package root is a folder marketplace; the CLI prints how to install and writes nothing.

**Spec:** `docs/superpowers/specs/2026-10-04-1.7.0-fleet-pane-design.md`. **Ledger:** `.omelette/ledger-1.7.0.md` (the spike's results of 2026-10-04 are the source of every claim about the engine below).

**Read:** the spec; the ledger's spike lines; the `plugin-authoring` skill, its `reference.md`, `examples/pane.tsx`, `examples/tool-call.ts`, `examples/pane-state.d.ts`, and `types/claude-code.d.ts` written by Claude Code 2.1.289 (declarations of `tool.call`, `agent.spawn`, `turn.step`, `classic.SubagentStop`, `session.measure`, `ui.open`, `ui.close`, `ui.render`, `AgentInfo`, `SvgProps`, `TextProps`, `claude-code/testing`); the spike mod (`~/.claude/dev-mods/<session>/omelette-spike/hooks/register.tsx`); `docs/STATUS-FEED.md` (schema 2); `bin/omelette-fleet.mjs` 134–145 and 1840–1880 (the `rules` flags); the reference mod `claude-plugins-official/plugins/code-modernization/hooks/` (layout of files and tests only).

## Global constraints

- Zero runtime dependencies, Node >= 20, no build step. The pure files are plain ESM `.mjs` with JSDoc types and import nothing but each other — not `claude-code`, not `node:*`.
- The mod never refuses, rewrites or blocks: every hook returns `next(e)` (or `yield* next(e)`) with `e` unchanged, and a failure of the mod's own bookkeeping never reaches the result (`try`/`catch` around state writes; the engine's result is returned as received).
- `$` is always spelled `$.noun.method(...)` literally in `register.tsx` (the engine scans the source and refuses what it did not see); no `import()`; plugin files are imported by `import` declarations with their extension (`./model.mjs`).
- The guard's refusal logic, the env allowlist, the billing scrub, the write gates, every tool schema and the rules file's text are untouched. The CLI writes no Claude Code setting; `rules --mods` prints.
- No test spawns `claude` or a vendor CLI. The mod's `tests/*.test.ts` run only at the live gate (`claude plugin test`), never under `npm test`.
- Public repository: no personal data, no absolute home paths in committed files; fixtures use `/home/op` and made-up ids.
- Docs are maps, not prose; atomic commits by the session, tests in the same commit as the behaviour.
- Tested build: Claude Code 2.1.289. A coder who finds a declared shape differs from this plan stops and reports (`NEEDS_CONTEXT`), it does not improvise.

## Review Focus

Inputs the spec implies and a person will meet; each has its test in the task named.

1. A session resumed or a mod hot-reloaded while agents run: the model has no spawn events for them — they must appear from `$.agent.list()` with role and status, without model or effort until their next step (T2, `agents` event).
2. A status snapshot that is not JSON, is schema 1, names an unknown unit, or is 40 minutes stale with a call in `active[]` (T2, `parseSnapshot`).
3. A pane 20 cells wide or 6 rows tall, and a role or tool name longer than its box (T3, the tree golden at 20 cells; `cut`).
4. Seven sub-agents on a 53-cell pane, two of them running and the oldest (T3, the `+N more` fold keeps running ones).
5. A tool call that never returns because the turn was interrupted: its activity must not stay on screen forever (T2: the loop's next `call` replaces it, its `stop` clears it, and a `tick` clears one older than 30 minutes).

## Task 2: the fleet model

**Bucket:** `omelette-coder` — the reducer's rules are stated below, their composition is the coder's.

**Files:** create `mods/omelette-fleet/hooks/model.mjs`, `feed.mjs`, `text.mjs`; fill `types/index.d.ts`; tests `test/mod-model.test.mjs`, `test/mod-feed.test.mjs`, `test/mod-text.test.mjs`.

**Interfaces (JSDoc typedefs in `model.mjs`, mirrored as exported types in `types/index.d.ts`; `PluginState` becomes `{ 'omelette-fleet': { fleet: FleetState } }`):**

```js
/** @typedef {{ id: string, kind: 'orchestrator'|'agent'|'unit', role: string, parentId?: string,
 *   model?: string, effort?: string, status: 'running'|'waiting'|'idle'|'reported',
 *   activity?: string, activityCallId?: string, since: number, callerId?: string,
 *   feed?: 'ok'|'none', lastEndedAt?: number, order: number }} FleetNode */
/** @typedef {{ at: number, from: string, to: string, label: string }} FleetLink   // node ids */
/** @typedef {{ contextPercent?: number, fiveHour?: number, sevenDay?: number, costUsd?: number }} FleetUsage */
/** @typedef {{ nodes: FleetNode[], history: FleetLink[], usage: FleetUsage, now: number, isOpen: boolean }} FleetState */

export const UNITS = ['gemini', 'grok', 'codex']
export const MAIN = 'main'
export function initialState(now)            // the orchestrator node (id 'main') and three unit nodes (ids 'unit:gemini' …), all idle, feed 'none'
export function reduce(state, event)         // pure; returns a new state, never mutates; an unknown event type returns the state as given
export function unitOfTool(tool)             // 'mcp__orion-grok__grok_code_review' → { unit: 'grok', tool: 'code_review' }; anything else → null
```

Events `reduce` takes, each with `at` (ms):

| `type` | Fields | Effect |
|---|---|---|
| `spawn` | `agentId, role, parentId, model` | adds an agent node (`status: 'running'`, `since: at`, `parentId` or `'main'`), or updates one that exists; history gains `parent → agent · Agent` |
| `step` | `agentId` (`'main'` for the main loop), `model, effort` | sets model and effort; a `reported` agent becomes `running` (it was resumed), `since: at`; the activity is not touched (a step happens between calls) |
| `call` | `agentId, callId, tool, subject, target?` | sets the loop's node `activity` (`subject` or the tool's name), `activityCallId`, `status: 'running'`; for a unit tool (`unitOfTool`), also sets the unit node running with `callerId`, `activity` = the tool part, `since: at`, and history gains `caller → unit · <tool part>`; for `SendMessage`, history gains `caller → <target node id, or the raw target> · SendMessage` |
| `return` | `agentId, callId` | clears the node's activity when `activityCallId` matches; a unit whose call it was becomes idle with `lastEndedAt: at` |
| `stop` | `agentId` | the agent becomes `reported`, `since: at`, activity cleared; history gains `agent → parent · report` |
| `agents` | `list: [{ id, type, status, parentId? }]` | adds agents the model does not know (role = `type`, status `running` for `running`, `waiting` for `idle`), updates the status of known ones except that a `reported` one stays `reported` while the engine says `idle` |
| `feed` | `snapshots` (from `parseSnapshot`) | per unit: `feed: 'ok'`; model, effort and `since` (the call's `startedAt`) for its running call; a call in `active[]` that this session's model does not have marks the unit running with `callerId: 'other'`; `lastEndedAt` from `lastEvent`; a unit with no snapshot keeps `feed: 'none'` |
| `usage` | `usage` | replaces `usage` |
| `tick` | — | `now: at`; clears any activity whose `since` is more than 30 minutes before `at` and returns that unit or agent to idle / its previous status |
| `open` / `close` | — | `isOpen` |

History is capped at 200, newest last. `order` is the node's spawn sequence, used by the layout.

`feed.mjs`:

```js
export function snapshotNames(names)        // keeps 'status-<unit>-<pid>.json' for the three units; anything else is dropped
export function parseSnapshot(text, now)    // → { unit, pid, active: [{ id, tool, model, effort, startedAt }], updatedAt, lastEndedAt?, isStale } or null
```

`parseSnapshot` returns `null` for text that is not JSON, not an object, `schema !== 2`, or a unit outside `UNITS`; times are parsed to ms; `isStale` is true when `active` is not empty and `updatedAt` is more than 30 minutes before `now` (a stale snapshot's `active` is returned empty).

`text.mjs`:

```js
export function cut(text, cells)            // by code points; longer text ends in '…' within `cells`; cells <= 0 → ''
export function duration(ms)                // 42 000 → '0:42'; 3 min 10 s → '3:10'; 12 min → '12m' from ten minutes up; 2 h 5 min → '2h'
export function shortRole(type)             // 'omelette-coder-medium' → 'coder-medium'; others unchanged
export function shortModel(id)              // 'claude-opus-5-5' → 'opus-5-5'; 'claude-fable-5-1' → 'fable-5-1'; others unchanged
export function familyOf(id)                // 'claude-opus-5-5' → 'opus'; a non-Claude id unchanged
export function subjectOf(tool, input)      // Bash → 'Bash: ' + the command's first two words; Edit/Write/Read/NotebookEdit → '<Tool> ' + the file's base name; a unit tool → its tool part; else the tool's name
export function clock(at, tzOffsetMinutes)  // 'HH:MM:SS' of `at` shifted by the offset `Date.prototype.getTimezoneOffset` reports
```

**Tests:** one test per row of the events table (state in, state out); a nested spawn (`parentId` an agent) and its `report` link going to that agent; a unit call from `main` and from a sub-agent (`callerId`); a `return` with a foreign `callId` changes nothing; `reduce` does not mutate its input (deep-frozen input); history's cap at 200; the five Review Focus cases 1, 2 and 5; `unitOfTool` on `mcp__orion-grok__grok_code_review`, `mcp__x__gemini_deep_research`, `mcp__omelette__get_usage` (null), `Bash` (null); `parseSnapshot` on the STATUS-FEED example verbatim, on schema 1, on garbage, on a 40-minute-stale snapshot; each `text.mjs` function on its boundary values; a test that `UNITS` equals the names of the directories under `units/`.

**Verify:** `npm test` green.

**Commit:** one — the three files, the contract, their tests.

## Task 3: the terminal drawing and the live module

**Bucket:** `omelette-coder` — the geometry is stated; the grid code and the hooks are the coder's.

**Files:** create `mods/omelette-fleet/hooks/layout.mjs`; rewrite `mods/omelette-fleet/hooks/register.tsx`; tests `test/mod-layout.test.mjs`; create `mods/omelette-fleet/tests/register.test.ts` (live gate only).

**Interface:**

```js
/** @typedef {{ text: string, tone: 'plain'|'live'|'dim' }} Segment */
export function layout(state, { columns, rows, isAscii, tzOffsetMinutes })   // → Segment[][], one array per screen row, no row longer than `columns` cells
export function plainRows(rows)                                               // → string[], segments joined, right-trimmed (for tests and for the SVG's alt)
```

**Geometry (graph, `columns >= 53` and `rows` enough for it):**
- Row 1 is the header: `ctx 31% · 5h 11% · 7d 71% · $646`, each figure left out when absent; row 2 is blank.
- A box is 17 cells wide and 5 rows tall (frame, three content lines, frame); boxes in a row are one cell apart. A content line is a space and at most 14 cells.
- Agents shown per row `n = min(6, floor((columns + 1) / 18))`; when the session has more, the row is its first `n − 1` by this order — running and waiting first, then `reported` by newest `since` — and a last box `+K more` (line two `<x> running` when hidden ones run, else blank; line three blank; its link is live when a hidden one runs). Within the row, boxes are ordered by `order`.
- Total width `W = max(53, shown agents × 18 − 1)`; each layer is centred in `W`; the orchestrator's box is 27 cells wide, its centre column `floor(W / 2)`.
- Between the agent row and the orchestrator, one bus row: a horizontal line from the leftmost to the rightmost of {box centres, the orchestrator's centre}, each column's glyph chosen by which of up / down / left / right it joins (`└ ┴ ┘ ┬ ┼ │ ─`); the frames carry `┬` / `┴` at those columns. The same below, to the units. With no agents there is no agent row and no upper bus.
- Agent box lines: `<glyph> <shortRole>`; `<familyOf(model)> · <effort>` (blank until known); the activity, or `reported <duration>` / `waiting <duration>`. Unit box lines: `<glyph> <unit>`; the running tool, or `idle <duration since lastEndedAt>` / `idle` / `no feed`; when running, `← <caller's role>` if the caller is not the orchestrator (`← other session` for `'other'`), else `<model> <duration>`. Orchestrator lines: `● orchestrator`; `<shortModel> · <effort> · <contextPercent>%`.
- Tones: a running agent's link (its frame junction, the bus cells between its centre and the orchestrator's centre, the orchestrator's junction) is `live`; the same for a running unit whose caller is the orchestrator; a box that is idle or reported, and every bus cell no live link covers, is `dim`; the rest `plain`.
- After the graph, a blank row, then history newest first, one link per row, `HH:MM:SS <from role> → <to role> · <label>`, as many as the remaining rows hold.

**`register.tsx` (the hooks of the spec's Data sources):**
- `session.start`: register the command; build the state if absent (`initialState`), send `agents` from `$.agent.list()` and `usage` from `$.session.usage()`; when `options.autoOpen` is not false, `void $.ui.open({ id, title })` (unasked: the engine seats it only on a wide terminal).
- `command.run` (`omelette-fleet`): open, or close on the argument `close`; answer one line.
- `agent.spawn`: after `next(e)`, a `spawn` event from `e.subagentType`, the result's `agentId` and `model`, and `e`'s loop id as the parent; return the result as received.
- `turn.step` (an async generator): a `step` event only when the loop's model or effort differs from the node's (one state write per change, not per request); `return yield* next(e)`.
- `tool.call`: a `call` event before `next(e)` (subject from `subjectOf`, `target` for `SendMessage`), a `return` event after it in a `finally`; the result is returned as received.
- `classic.SubagentStop`: a `stop` event; `return next(e)`.
- `session.measure`: a `usage` event; `return next(e)`.
- The tick: while the pane is open, `$.clock.every(1000, …)` sends `tick` and, every second tick, reads the fleet home (`$.env.get('OMELETTE_HOME')`, else `<$.env.get('HOME')>/.omelette`) with `$.fs.list` and `$.fs.read` and sends `feed`; `ui.close` cancels it and sends `close`.
- The status line: when the pane is closed, `$.ui.status` shows `fleet: <running roles and units, a unit with its duration>`, cut to 60 cells, and `undefined` when nothing runs.
- `ui.render` on the pane: `layout` with the pane's `bodyColumns` and viewport rows, `isAscii` from `NO_COLOR` or `TERM=dumb`; each row a `Text` whose children are one `Text` per segment — `live`: the theme's accent colour and `bold`; `dim`: `dimColor`.

**`tests/register.test.ts` (run by the session with `claude plugin test`):** the module registers the command; a spawn, a step, a tool call and a stop raised through the kit leave the state with the agent `reported`, its model set and three history links; the pane mounted on `terminal` at 53 columns draws the frames; no hook changes the result its `next` returned.

**Verify:** `npm test` green; `claude plugin validate` and `claude plugin test` pass (the session). Live: a session with one coder and one unit call watched in the pane, wide and narrow, and with `NO_COLOR=1`.

**Commits:** (1) `layout.mjs` and its tests; (2) `register.tsx` and `tests/register.test.ts`.
