# 0.3.7 · P2 — the `usage:` header and `results --stats`

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development (or superpowers:executing-plans). Steps use `- [ ]`. **Coder sub-agents never commit** — the last step of every task is a report to the orchestrating session, which reviews, runs the tester and commits on `feat/0.3.7`.

**Goal:** A spooled result says what it cost, and one command totals it. Every record gains an optional `usage:` header line written from the object the adapter already hands the status feed, and `omelette-fleet results --stats [<unit>] [--since <when>]` reads the spool back as one row per unit and a total — calls, `ok/error/cancelled`, partial, wall time, bytes, tokens in / out — without starting a server or spending anything.

**Architecture:** Three files change. `core/results.mjs` gains one `HEADER_KEYS` entry (`usage`, after `effort`), the render/parse rules for it, and a `stats({ since })` method on the store that walks the same headers a listing walks. `core/unit.mjs` puts the adapter's `usage` object into the record `finish()` hands `onResult` — the same object `status.end()` already receives. `bin/omelette-fleet.mjs` gains a `--stats` mode on `cmdResults`, a `--since` window and two formatters. Doctor, the status feed's schema, the write ceiling, the env allowlist and the tool schemas are untouched.

**Tech Stack:** Node ≥ 20, zero runtime dependencies (`node:` builtins only), plain ESM, `node --test test/` with fake vendor binaries.

**Spec:** `docs/superpowers/specs/2026-09-10-0.3.7-design.md` — **section M3 is this package**, and only M3.

**Master plan:** `docs/superpowers/plans/2026-09-10-0.3.7-master.md`. Its "Shared interfaces" block is binding: `HEADER_KEYS` gains `'usage'` after `'effort'`; `renderResult` writes the line only when `r.usage` is an object with numeric fields; `parseResult` returns `usage: { input, output, cachedInput?, reasoning? } | null`; `onResult({...})` from `finish()` carries `usage`; the command is `results --stats [unit] [--since <ISO date | 24h | 7d>]`; an empty spool prints `no results`.

```js
/**
 * One token count as the header writes it: a finite number — or the numeric
 * string a CLI that counts in strings would send — rounded, never negative.
 * `null` means "not a count", and the caller decides what that means.
 */
const tokens = (v) => {
  const n = typeof v === 'number' ? v : (typeof v === 'string' && v.trim() !== '' ? Number(v) : NaN);
  return Number.isFinite(n) ? Math.max(0, Math.round(n)) : null;
};

/**
 * The optional `usage:` line, or `null` for "this call reported no tokens",
 * which is NOT the same as zero and is not written as one. Both halves of the
 * pair are required: a run that reported only its output tokens is a run
 * nobody can total.
 */
function usageLine(usage) {
  if (!usage || typeof usage !== 'object') return null;
  const input = tokens(usage.input);
  const output = tokens(usage.output);
  if (input === null || output === null) return null;
  const parts = [`input=${input}`, `output=${output}`];
  const cachedInput = tokens(usage.cachedInput);
  if (cachedInput !== null) parts.push(`cachedInput=${cachedInput}`);
  const reasoning = tokens(usage.reasoning);
  if (reasoning !== null) parts.push(`reasoning=${reasoning}`);
  return `usage: ${parts.join(' ')}`;
}

/**
 * The inverse of `usageLine`. A key we do not know is ignored, exactly as an
 * unknown HEADER key is — a later version may add one — and a line without a
 * usable pair is `null`: the line was there and said nothing.
 */
function parseUsage(value) {
  const u = {};
  for (const part of String(value ?? '').trim().split(/\s+/)) {
    const eq = part.indexOf('=');
    if (eq <= 0) continue;
    const key = part.slice(0, eq);
    if (!USAGE_KEYS.includes(key)) continue;
    const n = tokens(part.slice(eq + 1));
    if (n !== null) u[key] = n;
  }
  return Number.isFinite(u.input) && Number.isFinite(u.output) ? u : null;
}
```

```js
/** The file body: the header block, then the text verbatim. */
export function renderResult(record = {}) {
  const r = record && typeof record === 'object' ? record : {};
  const head = HEADER_KEYS.map((key) => {
    if (key === 'promptPreview') return `promptPreview: ${JSON.stringify(line1(r.promptPreview, 200))}`;
    // The only key that may write NO line: `null` drops out below.
    if (key === 'usage') return usageLine(r.usage);
    if (key === 'durationMs') {
      const n = Number(r.durationMs);
      return `durationMs: ${Number.isFinite(n) ? Math.max(0, Math.round(n)) : 0}`;
    }
    if (key === 'partial' || key === 'detached') return `${key}: ${flag(r[key])}`;
    const v = line1(r[key], key === 'cwd' ? 1024 : 200);
    return v ? `${key}: ${v}` : `${key}:`;
  }).filter((l) => l !== null);
  return ['---', ...head, '---'].join('\n') + '\n' + String(r.text ?? '');
}
```

### Task 3: the store counts its own spool

**Files:** Modify `core/results.mjs` (`scan()`'s `rows.push({…})` ~lines 226–235; a new `stats()` before the store's `return {…}` ~line 327, and that return line). Modify `test/results.test.mjs` (append three tests). Nothing else.

**Interfaces**

*Consumes:* T1's parsed `header.usage`; `scan()`'s existing `size` and `readable` fields.

*Produces:* one new store member —
```js
store.stats({ since = null } = {})
// → { calls, ok, error, cancelled, partial, durationMs, bytes, reported, input, output }
//   every field a number; `since` is an epoch in ms (anything else = no window);
//   `reported` is how many of `calls` carried a token pair, and `input`/`output`
//   are the sums over THOSE calls only.
```
`{ write, list, read, prune, stats, dir }` is the new store shape. `list()`'s entry shape is deliberately **unchanged** — `test/results.test.mjs` pins it with a `deepEqual`, and nothing outside `--stats` needs bytes or tokens per row.

**Ambiguity resolved:** `bytes` is the size of the records **counted in the row**, not of the directory: with `--since` the two differ, and a filtered row that quoted the whole directory's size would be a number about something else. A record whose header cannot be read is counted by neither (it is not a call we know anything about), and a status that is none of `ok` / `error` / `cancelled` increments none of the three — `calls` is always the honest total.

```js
        acc.input += u.input;
        acc.output += u.output;
```

**Ambiguities resolved, and how**
1. **"Grok reports no usage"** (package brief). It does, since 0.3.1 — `{ input, output }`, either possibly `null`. The render rule is therefore "a numeric input AND output pair, or no line", which handles every real shape including a grok run that reported only one of the two. (T1.)
2. **`parseResult`'s three states.** The master types `usage` as `{…} | null`. Absent line → the key is absent (`undefined`), like every other header key the parser never saw; present-but-useless line → `null`. Consumers use `|| null`. (T1.)
3. **The record always carries `usage`** (`null` when unreported) rather than omitting the key. One shape, one assertion. (T2.)
4. **Where the aggregate lives.** `store.stats({ since })` in `core/results.mjs`, not in the CLI: the sizes and headers are already there, and a pure function next to `scan()` is testable without spawning the CLI. `list()`'s entry shape is deliberately not widened — a `deepEqual` pins it. (T3.)
5. **`bytes` means the counted records' bytes**, not the directory's: with `--since` those differ, and quoting the directory under a filtered row would be a number about something else. Unreadable files are counted by nothing. (T3.)
6. **A unit with no records gets no row**; no rows at all is `no results`. (T4.)
7. **The `total` row is always printed**, even for a single unit, because the spec says "one row per unit and a total". (T4.)
8. **The token cell shows `in / out` only.** `cachedInput` and `reasoning` are spooled per call and readable there; the spec fixes the row's columns. (T4.)
9. **`--stats` with an id or with `--path` is a usage error**, not a silently ignored flag — the CLI's existing habit is to refuse rather than guess. (T4.)
10. **The `since <ISO>` line** is an addition to the spec's output: one line, only when a window was asked for, so a filtered table is never mistaken for the whole spool. Flagged for the orchestrator in T5's report. (T5.)
11. **Relative windows are measured from now**, not from midnight. (T5.)
