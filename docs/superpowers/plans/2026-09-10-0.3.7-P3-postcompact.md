# 0.3.7 · P3 — `PostCompact`: the compaction summary on disk

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development (or superpowers:executing-plans). Steps use `- [ ]`. **The coder never commits.** Each task ends with a report to the orchestrating session, which reviews and commits it on `feat/0.3.7`.

**Goal:** A compaction replaces the session's context with a summary, and that summary is the only account of everything before it — held in a context the *next* compaction will replace in its turn. `HOOK_EVENTS` gains a sixth event, `PostCompact`, and the guard writes that summary into every `.omelette/ledger-*.md` of the project under a heading that is deliberately **not** a handoff heading. It is a record; the handoff block is still the session's to write. `handoff.compactSummary` (default `true`) switches it off, `doctor` says which way it is set, and neither the `SessionStart(compact)` print nor the `Stop` gate changes behaviour by one line.

**Architecture:** All the new behaviour lives in the self-contained guard, `hooks/omelette-guard.mjs`: a `postCompact(event)` handler that reads the transcript's tail through the existing `readBounded`, walks it backwards for the summary record, bounds and fence-closes the text, and appends it through the very append path `preCompact` uses — extracted into one `appendToLedgers(found, text)` so there is no second idea of what a ledger is or what may be written to one. The switch reaches the script the only way anything reaches it: `core/config.mjs` gains `HANDOFF_SCHEMA.compactSummary` and the existing `renderHookFile` / `parseHookHandoff` pair carries it into and out of the `{{handoff}}` literal without a line of change (both iterate the schema). `core/rules.mjs` appends `PostCompact` to `HOOK_EVENTS` and a sixth, matcher-less group to `hookSettingsSnippet`; `bin/omelette-fleet.mjs` needs no wiring code at all — `hookWiring`, `hookWiringAt`, `hooksLabel` and `nextStep` are already driven by `HOOK_EVENTS` — only its comments and one clause on the `handoff` line.

**Tech Stack:** Node ≥ 20, zero runtime dependencies, `node:` builtins only, plain ESM. `node --test` (`npm test`); the guard is exercised as a child process with a JSON event on stdin, exactly as `test/hooks.test.mjs` and `test/hooks-handoff.test.mjs` already drive it.

**Spec:** `docs/superpowers/specs/2026-09-10-0.3.7-design.md` — **M4 is this package**, plus M4's lines of the Docs and Testing sections. Package map and fixed interfaces: `docs/superpowers/plans/2026-09-10-0.3.7-master.md` ("Shared interfaces" is binding; P1, P2 and P4 are planned against those names in parallel).

**Verified facts this package rests on** (given in the brief, verified 2026-09-08 on Claude Code 2.1.263 — do not re-derive, do not contradict):

- After a compaction the transcript JSONL holds a record carrying `"subtype":"compact_boundary"` (a system record), and then a user record `{"type":"user","message":{"role":"user","content":"<the summary text>"},"isCompactSummary":true,…}`. The summary is the string `message.content`.
- The `PostCompact` hook input carries `session_id`, `transcript_path`, `cwd`, `hook_event_name` (`"PostCompact"`) and `trigger` (`"manual"` or `"auto"`).
- A transcript line the fill measurement reads looks like `{"type":"assistant","message":{"role":"assistant","model":"…","usage":{…}},"timestamp":"…"}`; nothing else in the file carries `usage`.

- `MATCHED_ON` gains nothing: `PostCompact` is matched on nothing, like `PreCompact`, `PostToolUse` and `Stop`.
- Windows: skip the symlink/FIFO test the way `test/hooks.test.mjs` already does (`{ skip: process.platform === 'win32' && '…' }`).

## Spec ambiguities resolved here (binding for the coder)

1. **Which summary record, when the tail holds several.** M4 says "the last record with `isCompactSummary: true` that sits after the last `compact_boundary` record". Resolved as ONE BACKWARD PASS with an early answer: scanning from the end, whichever of the two record kinds turns up first decides. A summary first means it is the last summary *and* it sits after every boundary in the read (a boundary further back is further back) → that is the summary. A boundary first means the newest summary in the tail belongs to an *older* compaction → `''`, silence, never a stale summary appended to today's ledger. Neither → `''`. That is exactly the spec's rule, in one pass and with no index bookkeeping.
2. **A summary record whose content is unusable.** The last summary record decides and nothing is scanned past it: if its `message.content` is missing, not a string and not an array, or yields no text, the answer is `''` and nothing is written. Falling back to an older record would write a summary that describes a different compaction.
3. **`message.content` as an array.** M4 says "the joined text parts". Resolved: elements are read as the transcript's own content parts — an object with a string `text`, or a bare string — joined with `\n`; everything else (a tool-use part, a number, `null`) contributes nothing. An array that yields no text is case 2.
4. **Where the 8 KiB cut falls.** Whole lines only: lines are kept while the running total (line + its newline) stays within 8 KiB, and a `[… truncated]` line says the rest was dropped. **The cap is hard**, exactly as `lastHandoffBlock`'s is: a summary whose first line alone is over 8 KiB keeps no line at all, and the block is the `[… truncated]` marker under its heading — a record saying "there was a summary and it did not fit" beats silence. Trailing blank lines are trimmed before the marker, because the block supplies its own blank line.
5. **Which fence is closed.** The fence state is tracked over the lines that were **kept**, with the `FENCE` regex and the same closing rule `lastHandoffBlock` uses (` ``` ` or `~~~`, closed only by the same character at least as long). Left open at the end → the opener's own run is appended as the last line of the body, *after* the `[… truncated]` marker, so a truncation that happened inside a fenced block still ends inside it and the ledger's next append starts outside it.
6. **`trigger` when the event does not carry one.** `str(event.trigger, 'unknown')` — the same fallback `preCompact` already uses, so a malformed event yields `(trigger: unknown)` rather than `(trigger: undefined)`. The spec's `manual|auto` are the two values Claude Code actually sends.
7. **`handoff.enabled: false` does NOT switch the summary off.** `enabled` is documented (CONFIG) as "renders a guard whose `PostToolUse` and `Stop` handlers do nothing at all" — it is the nudge and the gate. `compactSummary` governs `PostCompact` alone: an operator who switched the reminder off still wants the record of what a compaction dropped. Hence doctor's line carries `summary on|off` in **both** branches, including the `nudge off` one.
8. **What doctor reports for a guard older than 0.3.7.** `parseHookHandoff` fills a key the literal lacks with the schema default, so a 0.3.6 guard reads as `summary on` while its script has no `PostCompact` handler at all. That is deliberate and unchanged from 0.3.4's rule for the other three keys: the line reports the literal **as the guard's own `AUTO_HANDOFF` would read it** (`HANDOFF_CONFIG.compactSummary !== false`), and a script that old is already flagged by the `hooks` line's `[run: omelette-fleet rules --hooks]`. No special case is added.
9. **Where the new clause sits on doctor's line.** Between `Stop gate on|off` and `ledgers: …`: the clauses that say what the guard does stay together, the project's own facts (`ledgers:`) and the scope note stay last, so the existing suffixes keep their meaning.
10. **The rules template's "one sentence".** Written as one new bullet in "Ledger and handoff", in the voice of its neighbours: one sentence of substance (what lands, under which heading, that it is a record and not the handoff) plus one short sentence naming the switch. A bullet that describes a mechanism without saying how to turn it off sends the reader to CONFIG for one word.
11. **`CHANGELOG.md` has no `## 0.3.7 — unreleased` heading at `abc0dc1`.** P1 or P2 is expected to create it. T7 therefore says: add the bullet under that heading if it is already there, and create the heading immediately above `## 0.3.6 — 2026-09-10` if it is not.

**One accepted risk, recorded rather than fixed:** the summary is Claude Code's own prose and is written **verbatim**. If it happens to contain a line that reads `## Handoff …`, `sessionStart` would print from there and `freshHandoff` would count it. Escaping or fencing the body would make the ledger's record of the compaction something other than what the model wrote, which the spec does not ask for — so it is left as it is, and the heading rule (M4's actual requirement) is what is enforced and tested. Worth one ledger line for the orchestrator; not worth inventing behaviour the spec does not fix.

 * ONE BLOCK, APPENDED TO EVERY LEDGER of a project that is ours to write. The
 * two compaction handlers take this same path — PreCompact's re-read stamp and
 * PostCompact's summary — because the rules about what may be written are the

 * append until somebody opens the other end.
 *
 * Then O_NOFOLLOW on the open itself, because the lstat and the append are two
 * syscalls: a link planted between them is what the flag answers.
 */
function appendToLedgers(found, text) {
  for (const name of (found.exists ? ledgerNames(found.dir) : [])) {
    const path = join(found.dir, name);
    let fd = null;
    try {
      if (!lstatSync(path).isFile()) continue;
      fd = openSync(path, constants.O_WRONLY | constants.O_APPEND | NOFOLLOW | NONBLOCK);
      if (!fstatSync(fd).isFile()) continue;
      writeSync(fd, text);
    } catch { /* ignore */ } finally {
      if (fd !== null) { try { closeSync(fd); } catch { /* already gone */ } }
    }
  }
}

/**
 * HOW MUCH OF THE SUMMARY GOES IN. What Claude Code hands back after a
 * compaction is a whole session in one string, and a ledger is read by people:
 * 8 KiB is a screenful and a half of it, which is the part anyone reads.
 */
const SUMMARY_MAX = 8 * 1024;

/**
 * `message.content` as text. Claude Code writes the summary as a plain string;
 * the array form — the shape every other message in a transcript has — is read
 * too, and only its TEXT parts, one per line. Anything else in such an array (a
 * tool-use part, a number, a null) contributes nothing, and content that
 * contributes nothing at all answers '' and is written nowhere.
 */
function summaryText(content) {
  if (typeof content === 'string') return content;
  if (!Array.isArray(content)) return '';
  const parts = [];
  for (const part of content) {
    if (typeof part === 'string' && part) parts.push(part);
    else if (isObject(part) && typeof part.text === 'string' && part.text) parts.push(part.text);
  }
  return parts.join('\n');
}

/**
 * …and the same text as a block that is safe to append: WHOLE LINES up to
 * SUMMARY_MAX bytes, a `[… truncated]` line when anything was dropped, and a
 * CLOSING FENCE when the lines that were kept left one open — a summary quoting
 * a code block is ordinary, and an unclosed fence would swallow every line the
 * ledger gains after it. Fences are counted exactly as lastHandoffBlock counts
 * them, and the closer goes AFTER the truncation marker, so a cut that fell
 * inside a fenced block still ends inside it.
 *
 * The cap is HARD, as it is there: a summary whose first line is longer than
 * SUMMARY_MAX keeps no line at all and the block is that one marker — a record
 * saying there was a summary and it did not fit beats no record. Trailing blank
 * lines go, because the block supplies its own blank line.
 *
 * @returns {string} the block's body, or '' when there was nothing to write.
 */
function boundSummary(text) {
  const kept = [];
  let bytes = 0;
  let fence = '';
  let dropped = false;
  for (const line of String(text || '').split(/\r?\n/)) {
    const size = Buffer.byteLength(line, 'utf8') + 1;
    if (bytes + size > SUMMARY_MAX) { dropped = true; break; }
    kept.push(line);
    bytes += size;
    const f = FENCE.exec(line);
    if (!f) continue;
    if (!fence) fence = f[1];
    else if (f[1][0] === fence[0] && f[1].length >= fence.length) fence = '';
  }
  while (kept.length && !kept[kept.length - 1].trim()) kept.pop();
  if (dropped) kept.push(TRUNCATED);
  if (fence) kept.push(fence);
  return kept.join('\n');
}

/**
 * THE SUMMARY OF THE COMPACTION THAT JUST HAPPENED, or ''. Claude Code writes
 * one JSON object per line: a compaction leaves a record carrying
 * `compact_boundary`, and then the summary itself — a record carrying
 * `isCompactSummary: true` whose `message.content` is the text.
 *
 * READ BACKWARDS, and whichever of the two turns up first decides. A summary
 * first is this compaction's summary: it is the last one in the tail, and it
 * sits after every boundary there, because a boundary further back is further
 * back. A boundary first means the newest summary in the tail belongs to an
 * OLDER compaction and this one wrote none that can be seen — which is silence,
 * not yesterday's summary appended to today's ledger. Neither is silence too.
 *
 * The LAST summary decides on its own account: if its content carries no text,
 * the answer is '' rather than the record before it, which describes a
 * different compaction.
 *
 * Only the last 256 KiB are read — the same tail the fill measurement takes —
 * so the first line of that read is usually half a record. It simply fails to
 * parse, like any other line that is not one.
 *
 * @returns {string} the bounded, fence-closed body, or '' when there is nothing
 *   here this compaction wrote.
 */
function compactSummary(path) {
  const text = path ? readBounded(path, TRANSCRIPT_TAIL_MAX, { tail: true }) : null;
  if (text === null) return '';
  const lines = text.split('\n');
  for (let i = lines.length - 1; i >= 0; i--) {
    const line = lines[i].trim();
    if (!line.startsWith('{')) continue;
    let rec = null;
    try { rec = JSON.parse(line); } catch { continue; }
    if (!isObject(rec)) continue;
    if (rec.subtype === 'compact_boundary') return '';
    if (rec.isCompactSummary !== true) continue;
    return boundSummary(summaryText(isObject(rec.message) ? rec.message.content : null));
  }
  return '';
}

/**
 * THE RECORD. One block per compaction, into every ledger of the project, under
 * `## Compaction summary <ISO> (trigger: …)` — a heading that is deliberately
 * not a handoff heading, so the SessionStart print never shows it and the Stop
 * gate never counts it as the block the session owes.
 *
 * Same ledgers and the same rules as PreCompact, because it is the same append
 * path, and NOTHING ON STDOUT on any path: this handler writes a file, it does
 * not talk to the session. A summary it could not find, a switch turned off and
 * a project with no `.omelette` are all the same silence.
 */
function postCompact(event) {
  if (!AUTO_HANDOFF.compactSummary) return;
  const found = ledgerDir(event);
  if (!found || !found.exists) return;
  const body = compactSummary(str(event.transcript_path));
  if (!body) return;
  appendToLedgers(found, `\n## Compaction summary ${new Date().toISOString()} (trigger: ${str(event.trigger, 'unknown')})\n${body}\n\n`);
}
