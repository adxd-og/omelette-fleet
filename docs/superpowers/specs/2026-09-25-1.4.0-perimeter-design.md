## Why

Two things ran over v1.3.0 on 2026-09-25 and are recorded in the 1.3.0 ledger and under `.omelette/reports/`:

- **The `claude-security` plugin** (whole repository, medium, 72 agents) passed four findings through its panel, and a live check on `omelette-coder-medium` ran the vendors against bait files: none refuted, one narrowed. All four exist unchanged at `d7180b2` and none was among the 50 candidates of the two Codex runs (MEASUREMENTS, "Security audit"). Three of them contradict the sentence SECURITY rests on, that a prompt-injected unit "has nothing to act with":
  - **F1/F2** `units/grok/adapter.mjs:233,279` — research and review runs get `read_file`, `grep`, `list_dir` **and** `web_search`, `web_fetch`, with a bare `--allow WebFetch` and `GROK_WEB_FETCH=1`. Live: `read_file` reached a sibling of `--cwd` (it is a working directory, not a sandbox root); `web_fetch` ran headless with no prompt; grok's own guard blocked `127.0.0.1`, so the loopback variant is refuted and the public-exfil leg stayed unresolved. Injected content can read any file the operator can and carry it out in a URL.
  - **F3** `docs/SECURITY.md:358` — the recommended agy rules, `read_file(*)` with `read_url(*)`, give a headless Gemini run the same reach and an egress. Live: with exactly those rules (the operator's own file, four `~/.ssh` deny entries aside), `gemini_research` read a file outside `cwd` with no prompt.
  - **F4** `bin/omelette-fleet.mjs:2604` — `doctor` prints `command`/`args` from the project's `.mcp.json` unsanitised; `JSON.parse` turns `\u001b` into a real ESC. Live: `^[[2K^[[1AINJECTED node` reached stdout from an entry named `orion-codex`.
- **The prompt audit** (`/claude-api prompt-audit`, target Fable 5.1 / Opus 5.5) found 12 dated patterns on the Claude-facing surface, nine of them in a tested patch: a coder definition that contradicts itself, rules lines written as a diff against earlier releases, a Grok `effort` contract missing `xhigh`, and benchmark warnings repeated in five places with "4.5 was" clauses (`.omelette/reports/prompt-audit-1.3.0.md`).

The four readers of the closing assessment agreed on one thing to keep at any cost: the units and their perimeter. This release repairs the perimeter and touches nothing else.

## P1 — Grok: two profiles, never both

**The rule.** No Grok run holds a local-read tool and a web tool at the same time. The claim SECURITY then makes is exact: a prompt-injected research run has nothing local to read, and a prompt-injected review run has no way out.

**Toolsets** (`units/grok/adapter.mjs`, the L1 constants):

| Tool | `webSearch: true` (default) | `webSearch: false` |
|---|---|---|
| `grok_research` | `web_search,web_fetch` — **no** `read_file`, `grep`, `list_dir` | no tools: the model answers from its own knowledge (math and STEM cross-checks, second opinions on text in the prompt) |
| `grok_code_review` | `read_file,grep,list_dir` — **no** web tools, whatever the config says | the same |
| `grok_image` / `grok_image_edit` | unchanged (`image_gen` / `image_edit`) | unchanged |

- `READONLY_TOOLS` and `READONLY_TOOLS_NOWEB` are replaced by two named sets, `RESEARCH_TOOLS` (`web_search,web_fetch`) and `REVIEW_TOOLS` (`read_file,grep,list_dir`); the allow rules `WebFetch`, `WebSearch` are added to research argv only, since only research has the tools they un-prompt. Review argv carries no `--allow` at all. `GROK_WEB_FETCH=1` stays in the child env for research; it is harmless for review (no `web_fetch` in L1) and simpler to keep on both than to branch the spawn.
- **The empty toolset.** `grok_research` under `webSearch: false` runs with no tools. The coder probes the CLI once (`grok -p ... --tools ''` or whatever form the CLI takes for an empty allowlist) and records the working form in the adapter header. If the CLI has no way to run with an empty allowlist, and only then, `grok_research` under `webSearch: false` refuses with `Error: grok_research is web-only; set grok.webSearch=true, or use grok_code_review for local files.` and CONFIG's `webSearch` row says so for grok. Never pass a read tool to make the flag happy.
- `cwd` on `grok_research` stays an accepted argument, because the schema is public and callers pass it: it sets the working directory and nothing else now. Its description says so ("the run's working directory; research has no local-read tools, so it reads nothing there").
- The prefixes: `NO_MUTATE_PREFIX` splits into a research prefix ("you have web search and web fetch and no local file access; answer in plain text") and a review prefix ("you read files under the directory you are pointed at; you have no web access; answer in plain text"). The `MUTATE_RE` intent gate stays on research only, as today.
- **Descriptions.** `grok_research`: web research and model Q&A, reads no local files; point Gemini at local files. `grok_code_review`: reads the tree, no web. Both descriptions and the unit `instructions` stop repeating the benchmark warning beyond one plain sentence (P4 carries the wording).
- **Docs.** SECURITY's "Grok — layers L1–L6" gets the two L1 lines and states the rule and what it buys: with no run holding both, the exfiltration channel F1/F2 describe needs no domain allowlist and no probe of the public leg. ORCHESTRATION's routing row and ADAPTERS say `grok_research` reads no local files. CONFIG's `webSearch` row gets the grok column. The rules template's routing row for Grok is unchanged (it names the tools, not their toolsets).
- **Residual, stated in SECURITY.** A research run can still put prompt text into a `web_search` query or a `web_fetch` URL; what it can no longer put there is the contents of any file. A review run can still write anything it read into its answer, which the session reads as untrusted text, as today.

## P2 — agy rules that say what they allow

Docs only (`docs/SECURITY.md`, "Recommended agy allow-rules", and the sentence in the Gemini layers section that points at it). No code: the package cannot pin agy's permissions from the outside (SECURITY already says so), so the fix is what the docs tell an operator to install and what they tell them it means.

- The recommendation becomes two rule sets, named for what they allow:
  - **Web research** — `read_url(*)` alone. Grounded research works; a prompt-injected run can send only what is in its prompt and what it fetched.
  - **Local files, opt-in** — add `read_file(*)` only when the operator wants `gemini_research` to read local images, PDFs and documents, and say in one sentence what that buys an injected page: any file the operator's user can read, sent anywhere. With it, the docs list deny rules for the credential files the fleet knows about, by exact path, because that is the only deny form the docs have seen work: `~/.ssh/*` (the operator names the files), `~/.config/gcloud/application_default_credentials.json`, `~/.aws/credentials`, `~/.codex/auth.json`, `~/.grok/` and `~/.gemini/` token files, `~/.omelette/` (the result spool). The list is illustrative and says so; the rule is "every file that authenticates something".
- The Gemini row of the routing table ("Reading local images / PDFs / screenshots") stays, with a pointer to the opt-in rule set.
- The threat-model sentence changes: a prompt-injected unit has nothing to act with **because no run reads local files and reaches the web at once**; for Gemini that holds only under the web-research rule set, and the opt-in set trades it away, knowingly.

## P3 — `doctor` prints text, not terminal control

One helper in `bin/omelette-fleet.mjs`, `visible(s)`: replaces every C0 and C1 control character and DEL (`/[\u0000-\u001f\u007f-\u009f]/g`) with its `\u`-escaped form (`\u001b`), so an operator sees exactly what the file holds and their terminal does nothing with it. Applied to every value `doctor`, `install` and `update` print that came out of project or user JSON: server name, `command`, `args`/target, scope, the `.mcp.json` line, `adoptPrefix`'s found prefix, and the message of a JSON parse error. The test plants a `.mcp.json` entry named for the adopted prefix (the live check showed an entry under another prefix is never printed) whose `command` holds `\u001b[2K` and asserts `doctor`'s stdout holds no byte below 0x20 other than `\n` and `\t`, and holds the escaped form.

## P4 — the prompt-audit patch

`.omelette/reports/prompt-audit-1.3.0.patch` lands as written, one commit per surface so a hunk can be reverted alone: the rules template (four hook bullets become one, the guard sentence becomes two plain sentences, the Grok line loses "improved in 4.6 but still") with its three tests re-pinned; the coder definition (one NEEDS_CONTEXT rule instead of two that disagree); the Grok adapter and catalog (P1 rewrites the same descriptions, so P4's Grok hunks are folded into P1's task rather than applied twice); the Gemini adapter's dated claim. The Gemini catalog hunk is applied at its source, `~/Desktop/Jaravis/server/gemini/gemini-models.js`, and synced here with `npm run sync:catalog` from Jaravis; this repository's copy is never edited by hand. The three `flag` items of the audit (the `GUIDE` appended twice per tool schema, capitalised contract words in the Gemini descriptions, the dated Flash price) stay as they are.

After the templates change, the managed files are re-rendered here and in Jaravis (`rules --agents --hooks`, not committed).
