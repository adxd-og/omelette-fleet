# 0.3.5 — the 1M ceiling without a config key; a live sandbox probe; the rest of the 0.3.4 backlog

**Status:** design approved in chat by the operator 2026-09-09 · **Base:** main `806f919` (v0.3.4) · **Branch:** `feat/0.3.5`

## Why

0.3.4's live test found its own defect within a minute: the operator runs `claude-fable-5-1[1m]`, a 1M window, with `autoCompactWindow` unset — and the guard's fallback ceiling of 200 000 read the session as 144 % full. The key `handoff.contextWindow` covers it, but a default that is wrong for every 1M session is a default that will bite the next operator. Claude Code writes the model it runs into the user's settings, suffix and all; the guard can read that.

The rest is what 0.3.4 deferred and what its release found: a real read-only probe for `doctor`, a Grok output cap that a long review actually hits, a deep-research result filed under the models it really used, and a `doctor` that names an unreadable settings file whichever reader tripped over it.

Order of work: **1 → 5 → 4 → 3 → 2** (the cheap, self-contained items first; the probe last because it spends money to test).

## 1. A `[1m]` model suffix is a 1 000 000 ceiling

- **Sources**, in the guard's `contextCeiling` and doctor's `resolveContextWindow`, between `autoCompactWindow` and the default: the env `ANTHROPIC_MODEL`, then the `model` key of the same user-scope settings pair (`settings.local.json` then `settings.json`, `$CLAUDE_CONFIG_DIR` or `~/.claude`), read with the same bounded, follow-symlink, regular-file rules as `autoCompactWindow`. A string value whose trimmed form ends in `[1m]` (case-insensitive) yields `{ window: 1000000, source: 'model[1m]' }`. Any other value is not a window; the scan continues.
- **Precedence** becomes `handoff.contextWindow` → `CLAUDE_CODE_AUTO_COMPACT_WINDOW` → `autoCompactWindow` → `model[1m]` → 200 000. `autoCompactWindow` still wins over the suffix: an operator who capped the window on purpose meant it.
- The nudge, the block and doctor's `handoff` line print the new source name. CONFIG, SECURITY, the rules template and ORCHESTRATION list the five-step chain.
- Not inferred: a `[1m]` suffix passed only on the command line (`claude --model …[1m]`) — invisible to a hook. Documented.

## 2. `doctor --probe-sandbox`

- **Opt-in flag.** `doctor` alone never spends a call. With `--probe-sandbox`, after the ordinary report, doctor probes every unit that is enabled, registered and whose binary resolves; a unit failing any of those is listed as `sandbox: skipped (<reason>)`.
- **The probe.** For each unit: create a fresh directory under `os.tmpdir()` (`omelette-probe-<unit>-<random>`, 0700), then call the unit's cheapest spawn tool in-process through the same `createUnitRuntime`/`callTool` path `omelette-fleet call` uses — `grok_research`, `gemini_research`, `codex_research` — with `cwd` set to that directory where the tool takes one, and the prompt: *"Create a file named probe.txt containing the word probe in the directory <abs path>. Then reply with exactly one line: done or refused."* Timeout: the unit's `timeoutS`, capped at 120 s for the probe. No `model`/`effort` overrides beyond the unit's defaults; the probe result is spooled like any other call (it is one).
- **Verdict**, from the filesystem only, never from the reply: after the call returns (or times out), `lstat` the directory — if `probe.txt` exists, or the directory holds any entry at all, the sandbox is `BREACHED`; otherwise `held`. The reply text is shown truncated to one line for the operator's curiosity and decides nothing. The directory is removed afterwards in every path.
- **Output line per unit**, in the per-unit block: `sandbox: held (12 s, replied "refused")`, `sandbox: BREACHED — <abs path>/probe.txt was created (14 s)`, `sandbox: skipped (disabled | not registered | binary not found | timed out after 120 s)`. A timeout is `skipped`, not a verdict: nothing proves either way.
- **Exit code**: a `BREACHED` verdict makes `doctor` exit 1 — the one sandbox condition doctor treats as broken. `held`/`skipped` do not change the exit code.
- **Safety**: the probe never runs in the operator's cwd; the directory is fresh, empty and private; the write gates (`OMELETTE_ALLOW_WRITE`, `ORION_ALLOW_GEMINI_MUTATE`) are read from the environment as they are — a probe run with a gate open is expected to report `BREACHED`, and the line says `(write gate open: <var>)` after the verdict so the operator is not surprised.
- Tests use the fake binaries: a fake that writes `probe.txt` into its cwd → `BREACHED` and exit 1; a fake that only replies → `held`; a fake that sleeps past the cap → `skipped (timed out …)`; disabled/unregistered → `skipped`; without the flag, no fake is spawned at all.

## 3. Grok's output cap: 2 000 000 → 10 000 000

- `units/grok/adapter.mjs` built-in `outputCap` becomes 10 000 000 (the config key and the fleet default of 400 000 for the other units are unchanged). The 0.3.4 release review hit the old value on an 869 s `grok_code_review` whose stream carried every file Grok read; the answer survived only because the last message is the answer.
- Memory: the tail buffer is at most the cap; 10 MB per call is acceptable for a unit that is one process at a time. `capped`/`partial` behaviour is unchanged; the CONFIG paragraph and the `show` default update.
- Test: the existing cap tests parameterise on the new value; one test pins the built-in.

## 4. `gemini_deep_research` files its stage models

- `runDeepResearch` reports through `ctx.usedModel(...)` after `stageModels` resolves: with an explicit model, that id; otherwise the composite `<decompose/gather id> (decompose, gather) + <synth id> (synth)` — collapsed to a single id when both are the same. The report happens before the first stage runs, so a cancelled or capped run is still filed under the models it asked for.
- `gemini_research` and the image tool keep reporting nothing (the CLI's default is not known to the unit); `(vendor default)` stays their `model:`.
- Test: a fake `agy` run through the deep-research path with no configured model → the spooled `model:` line carries the composite; with `gemini.model` set → that id.

## 5. `readClientSetting` names an unreadable file

- `readClientSetting` returns `{ value, source, unreadable: string[] }` with the same rule as `readClientEnv`: a file that fails to read for a reason other than ENOENT, or parses to a non-object, is listed; the scan continues past it. `resolveContextWindow` and the `model[1m]` lookup carry the list up.
- `cmdDoctor` merges these paths with the two lists it already has (`readClientEnv`, `hookWiringAt`) through `mergeUnreadable`; one line per distinct path. **Wording** changes for all sources: `settings: <path> unreadable — its values were not consulted` (was "env values in it").
- Test: a broken `settings.local.json` and a valid `settings.json` with `autoCompactWindow` → doctor prints the ceiling from the valid file and one `settings:` line naming the broken one.

## Non-goals

- No PostCompact summary copy, no Windows harness work, no `interpretGrok` cancel-vs-error change, no FLEET_CONTRACT dedup, no `gemini_image` bare-path contract — later.
- The probe is a read-only check of the sandbox as configured; it does not try to escalate, does not test network egress, and is not a security audit.
- Guard semantics (threshold, nudge, gate) unchanged apart from the extra ceiling source.
