# 0.3.7 — the M column: a contract that costs nothing when the rules are installed, a budget view, a ring buffer, the compaction summary on disk, a merge policy in config

**Status:** design approved in chat by the operator 2026-09-10 · **Base:** main `1bb5ed3` (v0.3.6 + the Linux mtime fix) · **Branch:** `feat/0.3.7`

## Why

The 1.0 backlog's M column: five items of about a day each, none a feature. Two save the operator something every day (M1 tokens in every session, M3 a view of what a plan cost); one removes a known allocation pattern (M2); one closes the last gap in the handoff story (M4); one makes the shipped process adoptable by teams that gate main with pull requests (M5).

Order of work: **M1 → M3 → M2 → M4 → M5**.

## M1. The fleet contract costs nothing when the rules are installed

Today every unit server returns `FLEET_CONTRACT` (~300 tokens) plus its own line from `initialize.instructions`; three servers, three copies, resident in every session that has the fleet — including sessions whose project already carries `.claude/rules/omelette-fleet.md`, which states everything the contract states and more.

- **Rule.** At `initialize`, a server looks for the rendered rules file in its own process cwd (`<cwd>/.claude/rules/omelette-fleet.md`, the file `rules` writes; Claude Code starts an MCP server in the session's project directory — the spooled `cwd:` headers show it). Present and carrying our marker → **short contract**: one line `omelette-fleet: read-only unit; the operating model is in .claude/rules/omelette-fleet.md — the units propose, you apply.` plus the unit's own line. Absent, unreadable or not ours → the **full contract**, as today.
- **Global rules count too**: `~/.claude/rules/omelette-fleet.md` (or `$CLAUDE_CONFIG_DIR`) is checked after the project's, with the same marker test.
- **Override**: config key `contract: auto | full | short` (top level, default `auto`) for operators who want the full text always or never; `show` lists it.
- **Doctor** prints one line per project: `contract: short (rules installed here)` / `full (no rules file in <cwd>)` / `full (contract=full)`.
- Tests: initialize against a temp cwd with and without a rendered rules file; a rules file without our marker → full; `contract=short` with no rules → short; the unit's own line is always present.

## M2. The tail buffer is a queue

`runProcess` keeps the last `outputCap` characters of stdout by concatenating every chunk onto a string and slicing; the peak is the cap plus one chunk and each chunk costs a copy of the whole tail.

- **Rule.** Chunks go into an array with a running byte total; while `total - chunks[0].length >= outputCap` the head is dropped; on close the array is joined once and the join's leading excess sliced to exactly `outputCap`. `capped` is true when anything was dropped or sliced — same meaning as today. The transient of one chunk above the cap remains (a chunk must be held to be measured); the repeated whole-tail copy goes.
- Behaviour is unchanged for every caller: same `stdout`, same `capped`, same `stderr` handling (unchanged, it has its own small cap). Existing cap tests pass unchanged; one new test drives 50 MB of 64 KiB chunks through a 4 MB cap and asserts the result equals the last 4 MB and that the process's heap did not exceed cap + 8 MB (measured with `process.memoryUsage().heapUsed` deltas, generous bound, skipped on CI when the runner is under 2 GB).

## M3. `results --stats`: what a plan cost

- **Data.** The spooled record gains a `usage:` header — `input=<n> output=<n> [cachedInput=<n>] [reasoning=<n>]` — written from the adapter's reported usage when there is one (Codex and Gemini report; Grok does not), otherwise the line is absent. Older records without the line are read as "no usage". `parseResult` tolerates the new key (unknown keys are already ignored by older readers).
- **Command.** `omelette-fleet results --stats [unit] [--since <ISO date | 24h | 7d>]` prints one row per unit and a total: calls, `ok / error / cancelled`, partial count, wall time (sum of `durationMs`, `h m s`), spool bytes, `tokens in / out` where every record had usage, `n/a (<k> of <n> calls reported)` where some did not. `--since` filters on `startedAt`; default: everything the spool holds (retention already bounds it). Exit 0 always; an empty spool prints `no results`.
- **Doctor** does not change (the spool line it prints stays).
- Tests: a fixture spool with mixed units, statuses, one record without `usage`, one with `cachedInput`; `--since 24h` boundary; per-unit filter; old-format record (no `usage` line) tolerated; empty spool.

## M4. `PostCompact` puts Claude Code's compaction summary on disk

- **Rule.** `HOOK_EVENTS` gains `PostCompact` (no matcher); the snippet gets a sixth group. On the event the guard reads the transcript's tail (same bounded reader as the fill measurement), finds the last record with `isCompactSummary: true` that sits after the last `compact_boundary` record, and appends to **every** `ledger-*.md` in `<cwd>/.omelette/` (same rules as the PreCompact stamp: regular files only, `O_NOFOLLOW`, silent on failure) one block:
  ```
  ## Compaction summary <ISO> (trigger: manual|auto)
  <the summary text, bounded to 8 KiB, fences closed>
  ```
  The heading is not a handoff heading, so `SessionStart(compact)` never prints it and the Stop gate never counts it as fresh. When no summary record is found (a transcript whose format changed), nothing is written and nothing is said.
- **Config**: `handoff.compactSummary` (boolean, default `true`); rendered into the guard's `{{handoff}}` literal; `set handoff.compactSummary=false` turns it off.
- **Docs**: the rules template's "Ledger and handoff" gains one sentence (the summary lands in the ledger for the record; the handoff is still yours); CONFIG lists the key; SECURITY notes the guard reads the transcript for this too.
- Tests: fake transcript with a `compact_boundary` then an `isCompactSummary` record → block appended to two ledgers, bounded, fences closed; no summary record → nothing; `compactSummary=false` → nothing; a symlinked ledger skipped; the SessionStart print still shows only the last `## Handoff`.

## M5. Merge policy is config

- **Config**: top-level `workflow` block with `merge: session | pr` (default `session`). Rendered into the rules template through `{{merge}}`: `session` keeps today's sentence ("The session merges the branch into main itself…"); `pr` renders "The session opens a pull request from the feature branch and never merges into main itself; merging is the operator's or the repository's gate." ORCHESTRATION carries both variants in one paragraph.
- **Install and doctor** print one line: `merge policy: session` / `pr`, and, when `session` is set and the repository looks PR-gated (a `.github/PULL_REQUEST_TEMPLATE.md` or `CODEOWNERS` exists, or `gh api repos/:owner/:repo/branches/main/protection` answers 200 when `gh` is present), add `— this repository looks PR-gated: consider set workflow.merge=pr`. Never more than a hint; no network call without `gh` on PATH, and its failure is silent.
- Tests: render both variants; `set workflow.merge=pr` round-trips; a repo with a PR template gets the hint; `gh` absent → no call, no hint from that source.
