# 0.3.3 — no paid answer is lost: spool, progress, cancellation; handoff after compaction; doctor under any prefix; `capped` for every unit

**Status:** design approved in chat by the operator 2026-09-08 · **Base:** main `eabe1b3` (v0.3.2 + the untracked `.claude/` chore) · **Branch:** `feat/0.3.3`

## Why

On 2026-09-06 a `codex_code_review` ran 1081 s and finished `ok`; Claude Code had abandoned the request at 900 s (`MCP_TOOL_TIMEOUT`). The answer went to a dead request, nothing persisted it, the operator paid twice. Reading the docs for the fix turned up a second wall the fleet was already leaning on: since Claude Code 2.1.203 a **stdio tool call that sends neither a response nor `notifications/progress` for 30 minutes is aborted for idleness**, whatever the wall-clock limit says — and no unit sends progress. Grok's 1800 s sits on that line; a long Codex review is past it.

0.3.3 makes the fleet keep its answers: progress while a child runs, a spool every result lands in, a fetch for what the client dropped, a defined answer to cancellation, and a `doctor` that names both walls. The rest of the release is the 0.3.2 backlog: the handoff block printed after compaction, `doctor` recognising the operator's servers under any prefix, and `capped` honoured by Gemini and Codex the way Grok already does.

Order of work, so the incident class is closed even if the last steps slip: **1 (spike + progress + doctor) → 2 (spool + fetch) → 3 (cancel) → 4 → 5 → 6**.

## 1. Progress notifications and the two `doctor` walls

### 1a. Spike first: does Claude Code send `_meta.progressToken`?

MCP progress can only be sent for a request whose client supplied `params._meta.progressToken`. One-line spike in `core/jsonrpc.mjs`: log `_meta` of every `tools/call` to stderr under an env flag, run one real call, read the unit's stderr. Record in the ledger as `verified`. The spike code is throwaway; the fact decides how 1b is worded, not whether it is built.

### 1b. `notifications/progress` while a child runs

- `createHandler` passes the request's `progressToken` (when present) into `callTool` via a per-call context; the runtime emits `{ method: 'notifications/progress', params: { progressToken, progress: <seconds elapsed>, message: '<unit> <tool> running · 90s' } }` every **30 s** while a spawn (or a pipeline of spawns) is in flight, through a `notify(msg)` callback `serve` gives the handler. Nothing is sent without a token; nothing is sent after the response.
- `progress` is elapsed seconds, no `total` (unknown by construction). The message is one short line.
- Tests: handler with a token emits on a fake clock; without a token emits nothing; nothing after the response; the notification is a valid JSON-RPC notification (no `id`).

### 1c. `doctor` names both walls

Two informational lines, never a fault, after the registration lines:

```
mcp timeout   wall-clock: MCP_TOOL_TIMEOUT=2000000 ms (~/.claude/settings.json env) ≥ 1860000 needed · ok
              idle: CLAUDE_CODE_MCP_TOOL_IDLE_TIMEOUT unset → 30 min default; grok.timeoutS=1800 s reaches it — units send progress every 30 s when the client passes a progress token; otherwise set CLAUDE_CODE_MCP_TOOL_IDLE_TIMEOUT=0 or a per-server "timeout"
```

- **Wall-clock.** Sources, in Claude Code's precedence: process env, then `env` blocks of `.claude/settings.local.json`, `.claude/settings.json`, `~/.claude/settings.json` (via `CLAUDE_CONFIG_DIR` when set). Absent = the documented ~28 h default, reported as `unset (default ~28 h) · ok`. A per-server `timeout` on our registration entry overrides the env for that server and is read from the registration doctor already found. Needed = `max over enabled units of (timeoutS + 60 for gemini) * 1000`. Below needed → the line ends `· TOO LOW` and a snippet `{"env":{"MCP_TOOL_TIMEOUT":"<needed>"}}` follows, plus a `next` line.
- **Deep research bound**, one more line only when gemini is enabled: `gemini_deep_research worst case: 3 stages × 2 attempts × (timeoutS + 60 s) = <n> s` compared to the same wall-clock value. Informational; the docs say to run it deliberately.
- **Idle.** `CLAUDE_CODE_MCP_TOOL_IDLE_TIMEOUT` from the same sources; unset = 30 min for stdio; `0` = disabled. Compared with `max timeoutS`; the sentence above when a unit reaches it.
- Tests: precedence across the four sources; absent → default and `ok`; a per-server `timeout` wins; `TOO LOW` and the snippet; the idle line's three states (unset, `0`, explicit); no exit-code change in any of them.

## 2. Result spool and fetch

### 2a. Every spawn-tool result is spooled

- Path `<fleetHome>/results/<unit>/<resultId>.md`, directory `0700`, file `0600`, written by tmp-in-same-dir + `rename` (tmp name unique per pid+seq, created `O_EXCL`), synchronous, **fail-soft**: a write failure is one bounded stderr line and the call still returns.
- `resultId = <YYYYMMDDTHHMMSSZ>-<pid>-<seq>` generated by the **runtime**, independent of the status feed (`status.start` returns `null` when the feed is off). The status feed's `end` event and `lastEvent` gain `resultId` (additive field; schema stays 1, documented in STATUS-FEED.md).
- Written **before** the response is sent, for ok and error results alike, for `partial` too. Local tools (`_models`, `_result`) are never spooled. A call refused before the spawn (unknown model, mutate gate, disabled unit) is spooled as an error too — that is still an answer the caller may have lost.
- File shape: a fenced header, then the text verbatim.

  ```
  ---
  unit: codex
  tool: codex_code_review
  resultId: 20260908T142501Z-19312-1
  model: gpt-6-astra
  effort: xhigh
  startedAt: 2026-09-08T14:25:01.000Z
  endedAt: 2026-09-08T14:43:02.000Z
  durationMs: 1081000
  status: ok
  partial: false
  cwd: /Users/me/project
  promptPreview: "review the Movie app …"   (200 chars, control chars stripped, JSON-quoted)
  ---
  <text>
  ```
- **Retention after every write and at boot**: config `resultsKeep` (posint, default 50 per unit) and `resultsMaxBytes` (posint, default 50 MB per unit); oldest by `endedAt` from the header (filename as a tie-breaker) removed first; abandoned `*.tmp` older than an hour removed. Concurrent servers of the same unit prune the same directory: every unlink is try/catch.
- Config `results: false` (per unit or `defaults`) switches the spool off; `doctor` says so on the unit line.
- Security: the spool holds model answers, which can quote private source. It is under `fleetHome` (`~/.omelette` by default) with the same permissions as the status feed; documented in SECURITY.md next to the status feed. Never a path outside `fleetHome`; `fleetHome` is validated as before.

### 2b. Fetch: `<unit>_result` and `omelette-fleet results`

- New tool kind **`local`**: answered by the runtime without a spawn, never tracked by the status feed, never spooled. `catalog` tools become one case of it internally; `tools/list` is unchanged apart from the new tool.
- `<unit>_result` `{ id?: string }`:
  - without `id`: the newest result's header and text, then `Recent results:` — up to 10 lines `<resultId>  <tool>  <status>[ partial]  <durationMs>  <startedAt>`.
  - with `id`: that result. `id` must match `^[0-9TZ]+-\d+-\d+$`; anything else is refused before any path is built (no traversal, no symlink follow: the file is opened with `O_NOFOLLOW` semantics via `lstat` first).
  - unknown id / empty spool → `isError: true` with a one-line message.
  - The text is returned whole; it was bounded by `outputCap` when it was produced.
- CLI `omelette-fleet results [unit] [id] [--path]`: no unit → the last 10 across units, newest first; a unit → its last 10; an id → the file printed; `--path` prints the path only. Reads the same files, needs no server.
- Tests: spool written before the response (fake unit, fake clock); ids monotonic within a process and unique across a simulated pid reuse; retention by count and by bytes; `results: false`; `_result` with and without id, bad id refused, symlink refused; CLI listing shape; feed carries `resultId`; the feed off does not stop the spool.

## 3. Cancellation: `cancel: finish | kill`

- New config key `cancel` (`"finish"` | `"kill"`, per unit or `defaults`, **default `finish`**). Rationale in the ledger: units run on subscriptions with billing keys scrubbed, so a run that finishes after a cancel costs window quota, not money; the incident was a lost answer. The operator who mostly regrets runs sets `kill`.
- **Transport.** `serve` keeps an in-flight table keyed by the JSON-RPC `id` (number and string kept distinct, compared by type+value). `tools/call` registers before dispatch and is removed once, when the response is sent or dropped. `notifications/cancelled { requestId }` for an unknown or already finished id is ignored. For a live one:
  - `finish`: the entry is marked `abandoned`; the child runs on; the result is spooled (2a) with `status` as it ends and `detached: true` in the header and the feed's `end` event; **no response is sent** (the spec says receivers ignore it; sending one confuses a client that already timed out).
  - `kill`: every process group the request owns is `SIGKILL`ed (a pipeline may own several; a pending retry delay is aborted; later stages do not start); the feed ends the entry with status `cancelled`; the spool records `status: cancelled` with whatever text was captured; no response is sent.
- **Runtime.** `callTool` receives a `signal`-like cancellation context; `spawnFor` registers each child with it; `boundedRetry` observes it; deep research's gather stage observes it between spawns.
- **Stdin end.** `serve` no longer exits on `end` while in-flight runs exist: it stops reading, waits for them (each is bounded by its `timeoutS`), then exits 0. Documented limit: `finish` survives a client timeout and a client restart, not a `kill` of the server process.
- Tests: cancel-before-spawn, during a retry delay, during a gather, after completion (ignored); `finish` spools with `detached` and sends nothing; `kill` reaps the group (fake binary that spawns a grandchild) and aborts the retry delay; two concurrent requests, one cancelled, the other answered; stdin end with a run in flight waits and spools; string vs number ids.

## 4. Handoff after compaction

- **`SessionStart` with matcher `compact` prints the handoff**; `PreCompact` keeps stamping the ledgers and printing its one `HANDOFF:` line. Documented in Claude Code's hooks reference: `SessionStart` stdout is added to context; `PreCompact` stdout is not promised anywhere (our spike saw it once; a contract is not a sighting).
- Guard script gains the `SessionStart` branch: only when `source === 'compact'`; scans `<cwd>/.omelette/ledger-*.md` (regular files only, `lstat`, sorted); for each, the last `## Handoff` heading to the next `## ` heading or EOF, headings inside fenced code ignored; capped at **40 lines / 4 KB per ledger, 12 KB total**, with a `[… truncated]` line; each block preceded by `--- <file> · last handoff ---`. Reads capped at 1 MiB per file. Nothing to print → prints nothing (exit 0, no stdout).
- `HOOK_EVENTS` becomes `['PreToolUse', 'PreCompact', 'SessionStart']`; the settings snippet adds the `SessionStart` group with `"matcher": "compact"`; `doctor` reports `wired: PreToolUse, PreCompact, SessionStart` and `NOT wired` names the missing one. An installation at 0.3.2 wiring shows `SessionStart` missing with the usual paste line.
- Docs: rules template, ORCHESTRATION.md and README say the ledger must live under the session's cwd for the stamp and the print; a plan whose ledger lives in another repository gets neither.
- Tests: block extraction (last of several, none, fenced heading, caps, multiple ledgers, total cap); `source` other than `compact` prints nothing; snippet contains the third group; doctor wiring with two and with three events.

## 5. `doctor` under any prefix; hook wiring as a union

- `findRegistration` grows a name-independent scan: every server entry (user scope, every project scope in `.claude.json`, **and the project's `.mcp.json`**, which doctor does not read today) whose command is node and whose args path is exactly this checkout's `servers/<unit>.mjs` is ours; the name it was registered under is reported. A project-scope entry counts only for the project doctor runs in.
- Without `--prefix`, when nothing is registered as `omelette-*` and our servers are found under exactly one other prefix, `doctor` adopts it, prints `prefix        orion (found on the registrations)`, and the unit lines and `nextStep` use it. Two different prefixes → doctor lists both and keeps `omelette`. An explicit `--prefix` is unchanged, and so are `install` / `uninstall`.
- `hookWiringAt` returns the **union** of events wired across the settings files it read (order fixed by `HOOK_EVENTS`), still naming unreadable files and matcher problems.
- Tests: `orion-*` registrations → no false `install`, unit lines say registered; `.mcp.json` registration found; another project's entry ignored; two prefixes; union of `PreToolUse` in one file and the others in another; explicit prefix untouched.

## 6. `capped` for Gemini and Codex; deep research carries `partial`

- **Codex.** `extractResult` takes `capped` and `outputCap`. Capped and an `agent_message` parsed → the answer plus `[codex: output capped at N chars — the beginning of the stream was dropped; treat the answer as partial]` and `partial: true`. Capped and no message parsed → throw `codex output exceeded the N char cap and the final message was lost — raise codex.outputCap or narrow the task`, added to `isDeterministic` (no retry). Hard-killed and capped → the hard-kill branch answers first, both markers on a salvaged answer; the cap is named only when nothing was salvaged.
- **Gemini.** `interpretAgy` takes the same two. agy prints one JSON envelope, so capped and the envelope parsed → marker + `partial: true`; capped and no envelope → throw naming `gemini.outputCap` **instead of** the raw-stdout fallback (a fragment is not an answer). Same hard-kill precedence, same no-retry.
- **Deep research.** Each stage's `partial` is carried: any partial stage makes the report `partial: true` with a `[gemini: N of M stages returned partial answers]` line under the title; a gather that threw keeps its `_(gather failed: …)_` line.
- `codex_image` returns a bare path by contract; unchanged, noted in ADAPTERS.md.
- Tests: the two branches per unit, the kill-plus-cap case, no retry on the cap error, deep research partial propagation (a fake agy returning a killed gather).
