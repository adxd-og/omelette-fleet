# 0.3.2 — hardening from the 0.3.1 reviews, install UX, Windows signal

**Status:** scope approved by the operator 2026-09-06 · **Base:** main `a47753b` (v0.3.1)

## Why

0.3.1's three reviews and the live checks left a short list of sharp edges, two unverified mechanisms (`maxTurns`, `PreCompact` stdout) and one honest gap (Windows). 0.3.2 closes them and smooths the first-run path.

## 1. Doctor wiring: regex matchers

`hookWiringAt` compares the `PreToolUse` matcher literally. A matcher is a regex per Claude Code's hooks docs (`"Bash"`, `"Edit|Write"`, `"mcp__.*"`); a wired `"Bash|Edit"` reports `NOT wired`. Fix: absent / `""` / `"*"` cover Bash; otherwise `new RegExp('^(?:' + matcher + ')$').test('Bash')` inside try/catch (an invalid regex → not covering). Tests: `Bash|Edit` wired, `Edit` not, `.*` wired, `(` invalid → not wired with a clear label.

## 2. Guard block-list refinements + `maxTurns` fact

- `tag` with no further argument, `tag -l` / `--list` / `-n` are reads → allowed; `tag <name>` / `-a` / `-d` / `-f` stay blocked. `rebase --abort` is a read-ish recovery → allowed (`--continue`/`--skip` create commits → blocked). Tests for each.
- The spike result on whether `maxTurns` in a definition is honoured (this plan's spike (a)) is recorded in the docs: if honoured, the tester template's "if you hit the turn limit, say so" line stays; if NOT honoured, the line and the dynamic-maxTurns rule are reworded to "advisory" and the fact goes into the rules file.

## 3. Grok: front-truncated streams

`core/spawn.mjs` keeps the LAST `outputCap` (400 000) chars. For streaming NDJSON the first kept line is a fragment; when the final `result` line itself did not fit, `parseStream` reports `parsed: false` and `grokAnswer` falls open to the raw fragment as the answer.
- `interpretGrok` learns the cap: `ctx.spawn` result gains `capped: boolean` (spawn.mjs sets it when it sliced); when `capped && !parsed` → throw `grok output exceeded the ${cap} char cap and the final result line was lost — raise grok.outputCap or narrow the task`; when `capped && parsed` → append `[grok: output capped at N chars — the beginning of the stream was dropped; treat the answer as partial]` and `partial: true`.
- New per-unit config key `outputCap` (posint, default 400 000; Grok's builtin default 2 000 000 because thinking deltas ride the same stream), threaded to `spawnFor`. Documented in CONFIG.md and STATUS-FEED (partial reasons).
- Tests: spawn sets `capped`; interpretGrok's two branches; config key resolution.

## 4. `--remove --agents` removes the empty skill directory

`syncManagedFile` still removes no directories in general; the skills kind gets a post-remove step: `rmdirSync(dir)` ONLY if `dir` is `.claude/skills/omelette-test`, is empty, and is not a symlink; failure is silent. Test: dir gone after `--remove --agents`; a non-empty dir (user file inside) stays; a foreign SKILL.md is refused and the dir stays.

## 5. Hook snippet quoting per platform

`hookSettingsSnippet` quotes for the platform the CLI runs on: POSIX → single quotes (as now); `process.platform === 'win32'` → double quotes with backslashes doubled in JSON (`"node \"C:\\Users\\me\\.claude\\hooks\\omelette-guard.mjs\""`), and the docs sentence names both. `hookWiringAt` keeps matching on the script name. Tests with an injected platform (pass `platform` as a parameter, default `process.platform`).

## 6. Install UX: `install --rules` and doctor next-steps

- `omelette-fleet install --rules` = `install` + `rules --agents --hooks` in the cwd, then the snippet (same output as `rules --hooks`). `--dry-run` covers both halves.
- `doctor` prints ONE `next` line when something is missing, in order: `next          omelette-fleet install` (no registration) → `next          omelette-fleet rules --agents --hooks` (no project rules) → `next          merge the hooks snippet into .claude/settings.json (rules --hooks prints it)` (script present, not wired) → nothing when complete. Never a fault.
- README Quickstart becomes the three-line path: clone → `install --rules` → restart → paste the snippet → `doctor`.

## 7. PreCompact handoff (spike (b))

Interactive spike: run `/compact` in a session whose project has the guard wired and a ledger under `.omelette/`; observe whether the hook's stdout (`HANDOFF: …`) reaches the post-compaction context. If YES: the hook prints the last `## Handoff` block of each ledger (bounded to 40 lines) so the re-read is automatic; docs updated. If NO: unchanged hook; the rules file already says to re-read.

## 8. Windows signal

- CI matrix gains `windows-latest` (Node 20 and 22). The suite already skips symlink/chmod/FIFO tests on win32; expect failures around `core/spawn.mjs` (process-group `kill(-pid)`), path assertions, and quoting.
- Decision rule: if the failures are contained (spawn hard-kill via `taskkill /T /F` on win32; path/quoting fixes), fix them in this release and state "Windows: tested in CI on fake binaries; vendor CLIs not verified". If they are structural, keep the job as `continue-on-error` and document "macOS/Linux; Windows via WSL".

## Non-goals

No change to the write ceiling / env allowlist / billing scrub; the CLI never writes Claude's settings; no new dependencies; no `memory:` on shipped agents.

## Spikes first

(a) `maxTurns` honoured? — a `turns-probe` definition with `maxTurns: 3` asked to make six Bash calls; compare with an unlimited control. (b) `PreCompact` stdout visibility — interactive `/compact` in this project (the operator runs it; the orchestrator reads the result). (c) Windows CI job — push the matrix change on the branch and read the run.

## Testing

Unit tests per item as listed; CLI tests never need a vendor CLI; live: `install --rules --dry-run` shape, `doctor` next-lines in a scratch project, a capped Grok stream via a lowered `grok.outputCap` (e.g. 2000) on a real call.
