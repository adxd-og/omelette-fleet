## Why

Three measurements, all in MEASUREMENTS:

- **The handoff hooks over five compactions.** Every compaction this project has had was manual and already preceded by the session's own handoff block. The threshold nudge fired twice, both on a wrong 200 k window, never since; the compaction summary wrote seven blocks, three of them duplicates in ledgers they do not belong to. The one part that carried value is the print of the ledger tail at session start and after a compaction. Three of the four readers of the 1.3.0 closing assessment named this machine as the first thing to cut; the measurement agrees.
- **Planning cost with the scout map.** One measurement, confounded by a planner's dry run, shows no total saving; 1.4.0 was planned by the session with no map; a clean re-measurement would cost a release's planning twice for a tool used at most once per release and only when the planner is a fresh delegate. The mandate costs two rules bullets in every session.
- **The perimeter's next layer (1.4.0 backlog).** Astra's inventory of every documented environment name of grok 1.0.41, codex-cli 0.156.1 and agy 1.2.11 (`.omelette/reports/env-allowlist-research-1.5.0.md`, on file, not committed) classifies 144 grok names, 60 codex names and 70 agy names; the vendor wildcards `GROK_*`, `CODEX_*`, `AGY_*`, `GEMINI_*`, `GOOGLE_*` admit every class-C name (execution, egress, trust) that is not scrubbed by hand. 1.4.0 scrubbed twelve by name; a list that names what may pass is the design that does not need a scrub to keep up with a vendor.

## P1 — three hooks, not six

**What stays.** `PreToolUse` (the git guard for the shipped roles — untouched), `PreCompact` (one line into the ledger: `## Compaction <ISO> (trigger: …) — re-read this ledger before continuing`), `SessionStart` (the ledger tail printed into the fresh context, bounded as today: 40 lines / 4 KB per ledger, 12 KB in all). `HOOK_EVENTS` becomes `['PreToolUse', 'PreCompact', 'SessionStart']`.

**What goes.** The `PostToolUse` nudge, the `Stop` gate, the `PostCompact` summary, and with them the context estimator (window detection, the transcript scan, `handoff-state.json`), the config keys `handoff.threshold`, `handoff.contextWindow`, `handoff.compactSummary`. `handoff.enabled` stays and now means: the `PreCompact` stamp and the `SessionStart` print. An unknown key from an older config warns and is ignored, as today.

**The print after a compaction.** Claude Code runs `SessionStart` with `source: "compact"` after a compaction; the guard already handles that source. Nothing is lost by dropping `PostCompact`: the stamp is written before, the tail is printed after.

**Installs that wired six.** The rendered guard exits 0, silently, for `PostToolUse`, `Stop` and `PostCompact` (they are no longer in `HOOK_EVENTS`, but the file must not fail an operator whose settings still call it). `doctor`'s hooks line reports the three stale entries as "wired but no longer used — remove from settings.json", not as a fault; `rules --hooks` prints the three-event snippet. The settings files are never edited by the package.

**Docs.** CONFIG: "Handoff settings" shrinks to `handoff.enabled`; "The handoff hooks" describes stamp and print and says, in one line with a link to the measurement, why the rest went. ORCHESTRATION's handoff section follows. The rules file's line `omelette-fleet rules --hooks wires the ledger hooks…` stays true as written. MEASUREMENTS: "The guard's estimate against the engine" stays as history with one line saying the estimator is gone; "Not measured yet" loses N0 and the nudge-under-auto-compaction item; the guard's size before and after goes into a row.

**Tests.** `test/hooks-handoff.test.mjs`, `test/hooks-handoff-extra.test.mjs`, the `tester-0.3.7-*` files and every other test of the nudge, gate, summary and estimator are deleted with the code; the stamp and print tests stay; new tests: the guard exits 0 on the three retired events with no output, `doctor` names a stale entry, the settings snippet lists three events, the retired config keys warn.

## P2 — the map is a technique, not a rule

**Rules file.** Bullet 20 ("One scout map per release, never to a first review") is removed. Bullet 21 (the planner's brief) loses "map first, three pointers opened by hand (one false: whole map unverified), then only what the map lacks; the plan header lists map lines relied on and re-taken" and reads: a planner gets its spec section and the pointers the session hands it, and the plan header lists what it read. Bullet 19 (evidence pointers, `check`) stays byte for byte.

**ORCHESTRATION.** The "Scout map" row and the "A planner starts from the map" paragraph become one paragraph under a heading "The scout map, when a fresh planner needs one": what the map is, `check` on it, three pointers opened by hand, and when it earns its place (several packages planned by fresh delegates; not when the session plans). MEASUREMENTS' "Planning cost with the scout map" stays; "Not measured yet" loses "What the scout map saves" and gains nothing.

**Tests.** `test/evidence-pointers.test.mjs` re-pinned: the evidence bullet stays, the scout bullet is gone, ORCHESTRATION carries the optional technique; `rules-size` ceiling untouched (the file shrinks; report the size).

## P3 — explicit environment allowlists

**The rule.** Every unit declares `envPassthrough` as exact names only. `core/spawn.mjs` keeps pattern matching (`PREFIX_*`) for `OMELETTE_ENV_PASSTHROUGH` alone — the operator's escape hatch — and refuses a pattern in an adapter's list at unit load (`defineUnit` throws). The shared baseline `ALLOWED_ENV` is unchanged: it holds the proxy and certificate names, which by Astra's taxonomy are class C; they stay because they are how an operator's network works, and SECURITY says so.

**The lists** (from the report's "Pasteable adapter declarations", class A + verified class B; UNVERIFIED names excluded):

- grok: `GROK_HOME`, the auth-label/TTL/early-invalidation names, `GROK_OAUTH2_REFERRER`, the four version-constraint names, `GROK_DISABLE_AUTOUPDATER`, `GROK_CRASH_HANDLER`, the ask-user-question names, the compaction preference names, `GROK_FEEDBACK_TRACE_CARD`, the display and scroll preferences, `GROK_THEME`/`LC_GROK_THEME`/`GROK_APPEARANCE`/`LC_GROK_APPEARANCE`/`COLORFGBG`, `NO_COLOR`, `RUST_LOG`, the timeout names (`GROK_EXIT_TIMEOUT_SECS`, `GROK_SESSION_END_HOOKS_TIMEOUT_MS`, `GROK_MCP_STARTUP_TIMEOUT_SECS`, `MCP_TIMEOUT`, `GROK_MAX_WAIT_BLOCK_MS`), `GROK_SCREEN_MODE_SWITCH`, the two clipboard names, and the OTEL interval/timeout preferences. The exact list is the report's, copied into the adapter with the report's source column as a comment block.
- codex: `CODEX_HOME`, `CODEX_ACCESS_TOKEN`, `RUST_LOG`, `CODEX_EXEC_SERVER_EXIT_ON_STDIN_CLOSE`.
- gemini: `AGY_ADC_AUTH`, `AGY_CLI_DISABLE_AUTO_UPDATE`, `AGY_CLI_HIDE_LOGO`, `AGY_CLI_HIDE_ACCOUNT_INFO`, `AGY_CLI_DISABLE_LATEX`, `AGY_CLI_DISABLE_ESCAPE_SEQUENCE_OPTIMIZATIONS`, `AGY_CLI_CMD_OUTPUT_PERCENTAGE`.

The fleet's own knobs the adapters read through `envMap` (`GROK_DEFAULT_MODEL`, `GROK_TIMEOUT_S`, `GROK_MAX_TURNS`, `GROK_IMAGE_MAX_TURNS`, `CODEX_DEFAULT_MODEL`, `CODEX_EFFORT`, `CODEX_TIMEOUT_S`, `CODEX_WEB_SEARCH`, `AGY_DEFAULT_MODEL`, `AGY_TIMEOUT_S`, `AGY_BIN`, `GROK_BIN`, `CODEX_BIN`) are read by the unit process, not passed to the child; nothing changes there. `GROK_WEB_FETCH=1` stays as `extraEnv` on research spawns.

**Logins.** Grok device/browser login and Codex ChatGPT login rest on `HOME` / `GROK_HOME` / `CODEX_HOME`, all listed. API-key login for grok was already impossible through the fleet (`XAI_API_KEY` is scrubbed) and stays so: the subscription-only policy is unchanged, and `GROK_CODE_XAI_API_KEY`, the alias the report found unscrubbed, joins the scrub. agy Google-account login rests on stored credentials under `HOME`; ADC is the operator's choice through `AGY_ADC_AUTH`, listed; `GOOGLE_APPLICATION_CREDENTIALS` stays scrubbed and `GOOGLE_EXTERNAL_ACCOUNT_ALLOW_EXECUTABLES` stays scrubbed. The scrub list stays as belt-and-braces and is renamed `riskEnv` (the field `billingRiskEnv` keeps working as an alias for one release, with a load-time warning).

**Verification, before merge.** `doctor` on the operator's machine: every unit's version and login probe green through the new environment; one real call per unit (`omelette-fleet call <unit> <unit>_research '{"prompt":"reply with exactly: ok"}'`). This is the one live check the release cannot skip, because a missing class-A name is a broken login that the suite cannot see.

**Docs.** SECURITY's "The environment allowlist" section: the baseline, the per-unit exact lists (or a pointer to the adapter block), the escape hatch, the scrub, and the sentence that this is an environment policy, not configuration isolation (config files, hooks and MCP registrations the CLIs read on their own are listed under "Configuration the fleet did not choose", which gains `~/.codex/hooks.json` — observed running under `--ignore-user-config` — and agy's `~/.gemini` settings/hooks/MCP files). ADAPTERS' checklist: `envPassthrough` is exact names, with a link to how to classify a new one. CONFIG's `OMELETTE_ENV_PASSTHROUGH` row unchanged.

**Tests.** `defineUnit` refuses a pattern in `envPassthrough`; each unit's child env under a parent env carrying one name of each class (A passes, B passes, C absent, D absent) — a table-driven test over the report's classes; `OMELETTE_ENV_PASSTHROUGH=GROK_*` still admits a pattern; the alias warning.

## Out of scope
