# 1.1.0 — evidence travels with pointers: a report shape, one scout map per release, and `check`

**Status:** design approved in chat by the operator 2026-09-17 · **Base:** main `3dd368d` (v1.0.0) · **Branch:** `feat/1.1.0`

## Why

Multi-agent work multiplies reading: in 0.3.7 four planners each re-read `core/`, and coder and tester reports come back as free prose the session has to take on faith or re-derive. The fix is a funnel — explore once, pass compact evidence up — with one guard against the funnel's own failure mode: a digest that cannot be checked turns one agent's mistake into everyone's premise. So every line of evidence carries a pointer and a verbatim fragment, and a command verifies them mechanically.

Reviews are **not** part of the funnel: the first review of a change stays clean-context and never receives a scout map.

## 1. The pointer line

One grammar for reports and maps:

```
- `core/unit.mjs:435` · `const finish = (text, isError` · finish() closes the status entry and spools the record
```

`path:line` · a **verbatim fragment** of that line in backticks · the claim — three fields, all required, separated by ` · ` (space, U+00B7, space).

- **path** is relative to the project root, holds no whitespace, backtick or colon, and names **one** line: no range (`file:10-20`), no absolute path. Backticks around `path:line` are optional (both or neither). The line number is a positive integer; leading zeros are tolerated.
- **bullet** is optional: `-`, `*`, `+`, or an ordered marker (`1.` / `1)`), after optional indentation.
- **fragment** holds no backtick — choose one that does not need it — and must carry information: at least **8 characters** after whitespace normalisation, with an alphanumeric run of at least 3. A shorter or emptier fragment is `weak` (§4).
- **claim** is non-empty free text and is never checked.
- A line that *opens* like a pointer — optional bullet, optional backtick, `something:digits` where the something looks like a file path (it contains a `/` or a `.`, and no `://` — so `12:30 · lunch`, `key:1 · value` and a URL stay prose), and a ` · ` somewhere after — but does not parse under these rules is **`malformed`** (§4), not prose: evidence that silently fails to count is the failure this release exists to prevent. Every other line is prose and is ignored.

## 2. Report shape for `omelette-coder` and `omelette-tester`

Both templates (`agents/omelette-coder.md`, `agents/omelette-tester.md`) already ask for a full report to a path and a short reply. The full report gets fixed sections, in this order:

`## TASK` (one paragraph: what was asked) · `## FINDINGS` (pointer lines: what was built or observed, each where it can be seen) · `## DIFF` (files changed, one line each) · `## TEST RESULTS` (exact commands and the raw runner summary; the tester keeps every failure in full) · `## OPEN QUESTIONS` (decisions the brief left open, anything not done; `none` when none).

The short reply keeps its current fields. The rules template and ORCHESTRATION gain one bullet: reports come in this shape, and the session may run `omelette-fleet check <report>` before reading further.

## 3. One scout map per release

Rules text and an ORCHESTRATION section; no new shipped agent definition.

- **When.** Before planning a release of more than one package, the session briefs **one** scout (a read-only sub-agent) to write `.omelette/map-<plan>.md`, once. Planners and the coder receive the map instead of re-reading the modules it covers.
- **Shape.** First lines: `# Map — <plan>` and `commit: <hash>` (the commit the map was taken at). Then pointer lines grouped by module, factual only — *owns / exports / calls / reads / writes* — no judgement about quality or design. Last section, mandatory: `## Not read` — every directory or file the scout did not open, so silence is not read as absence.
- **Use.** The session runs `omelette-fleet check .omelette/map-<plan>.md` before handing the map on and again whenever the branch has moved. A consumer opens **three pointers of its own choosing** before relying on the map; one false line rejects the map whole. Stale lines (their file changed since `commit:`) are re-taken, not trusted.
- **Never to a first review.** A reviewer briefed with the scout's map inherits the scout's blind spots.

## 4. `omelette-fleet check <file.md> [--strict] [--require <n>] [--root <dir>]`

Read-only. Logic in `core/check.mjs` (pure apart from reading targets: `checkPointers({ text, root, changed, cacheBytes? }) → { pointers: [{ line, path, lineNo, fragment, status, foundAt? }], counts }`), a thin `cmdCheck` in `bin/omelette-fleet.mjs`.

- **Statuses.** `ok` — the fragment is on that line (both sides whitespace-normalised: runs of whitespace to one space, trimmed; the line must *contain* the fragment). `moved` — not on that line but elsewhere in the same file; the **nearest** line carrying it is named, ties going to the **smaller line number**. `mismatch` — nowhere in the file (a line number past the end is judged the same way: `moved` when the fragment is elsewhere, `mismatch` when nowhere). `missing` — no such file. `outside` — the path resolves outside `--root` (default: cwd), is absolute, is a symlink, or is not a regular file. `too-large` — the target exceeds 2 MiB. `weak` — the fragment is under 8 normalised characters or has no alphanumeric run of 3; it is not looked up at all. `malformed` — a line that opens like a pointer and does not parse (§1); it has no path to look up. `stale` — `ok`, but the file changed since the map's commit.
- **Staleness.** A `commit:` line within the first 20 lines of the checked file turns it on. A value of 7–40 hex characters (backticks around it tolerated) is used; **any other value** — a ref name, a tag, a hash with a trailing note — is *unusable*: nothing reaches git, and the run prints `staleness: not checked (unusable commit value)`. With a usable hash: `git diff --name-only --relative <hash> --` — the commit against the **working tree**, so uncommitted edits count — with `cwd = root`, `execFile` (no shell), 5 s timeout with `killSignal: 'SIGKILL'`. git absent, not a repository, unknown hash, timeout → `staleness: not checked (<reason>)`. No `commit:` line at all: staleness is off and nothing is printed.
- **The git child is boxed.** Its environment is built, not inherited: `PATH`, `HOME`, `LANG`/`LC_ALL` when set, plus `GIT_NO_LAZY_FETCH=1`, `GIT_OPTIONAL_LOCKS=0`, `GIT_TERMINAL_PROMPT=0`, `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL=/dev/null` (`NUL` on win32) — so `GIT_DIR`, `GIT_WORK_TREE`, `GIT_TRACE*`, `GIT_EXTERNAL_DIFF` never arrive. Arguments: `-c core.fsmonitor=false -c core.hooksPath=/dev/null -c diff.autoRefreshIndex=false diff --no-ext-diff --no-textconv -O/dev/null --name-only --relative <hash> --`. `diff.autoRefreshIndex=false` is not optional: without it the working-tree diff rewrites `.git/index` when a tracked file is stat-dirty (measured on git 2.38.1), and `check` writes nothing. What this does not cover (a repository-local `include.path`, a clean filter named in the repository's own config, alternates) is listed under best-effort in SECURITY.
- **Exit code.** `0` when every pointer is `ok` (or `stale` without `--strict`) **and** the number of *distinct* `path:line` pairs (keyed on the resolved path, so `a/../a/x.js:2` and `a/x.js:2` are one) is at least `--require` (default `1`, so an empty artifact does not pass; `--require 0` is for a report that says its findings are `none`). `1` otherwise; with `--strict`, `stale` and any `staleness: not checked` also give `1`. `2` for usage errors — no file, unreadable file, a checked file over 1 MiB, more than 2000 pointer lines, a bad flag, a root that is not a directory or vanishes — and a usage error wins over everything: no report is printed.
- **Output.** Optionally first `staleness: not checked (<reason>)`. Then one line per pointer that is not `ok`: `<status>  <path>:<line>  <fragment>` (+ `  → found at <n>` for `moved`; for `malformed`: `malformed  line <n>  <the line, trimmed, at most 120 chars>`). Then the summary: `check: <n> pointers · <ok> ok · <moved> moved · <mismatch> mismatch · <missing> missing · <outside> outside · <stale> stale`, with ` · <k> too-large`, ` · <k> weak`, ` · <k> malformed` appended only when non-zero (`<n>` counts malformed lines too). When the distinct count is below `--require`, one more line: `check: <d> distinct pointers, at least <k> required`. Nothing else; no colour when stdout is not a TTY.
- **Bounds and safety.** The checked file is the operator's choice and may live anywhere (reports sit in a scratchpad); it is read through the same bounded reader as a target — regular file, `O_NONBLOCK | O_NOFOLLOW`, at most 1 MiB. Target paths are resolved against the real path of root and refused when they leave it (containment by `path.relative`, so a root of `/` works); a symlink target is `outside`; a parent that resolves outside is `outside`. Each target is held once per run as **one representation** — its whitespace-normalised lines joined by `\n` plus a `Uint32Array` of line starts — so `ok` is a slice and `moved` is one `indexOf` forward and one `lastIndexOf` backward from the pointed line, not a scan per pointer. The cache is charged what it really holds (`2 × length + starts.byteLength`, after the read) against 32 MiB; past the budget a target is read and judged but not kept. At most 2000 pointer lines. The command writes nothing and never edits settings files.

## 5. Docs

README CLI table row for `check`; ORCHESTRATION sections for the report shape and the scout map (with their map rows — the docs-map test must stay green); the rules template gets **two bullets, short** (it is resident context in every session — the point of this release is fewer tokens); SECURITY one sentence (`check` reads files under the project root only and runs `git diff --name-only`); CHANGELOG `## 1.1.0`; `package.json` 1.1.0.

## 6. Tests

`test/check.test.mjs` on temp directories: ok; wrong line → `moved` with the found line; fragment nowhere → `mismatch`; no file → `missing`; `../` escape and absolute path outside root → `outside`; symlink target → `outside`; whitespace-normalised match; prose lines ignored; zero pointers fails by default and passes with `--require 0`; `--strict`; a temp git repository with two commits → `stale` on the changed file only; unknown hash and no git repository → `staleness: not checked`, exit unaffected without `--strict`; hostile `commit:` value (`--output=x`) is not passed to git; 2 MiB target → `too-large`; exit codes 0/1/2; after the review round: `weak` and `malformed` (every near-miss of §1: `+`/ordered bullets parse, `file:10-20`, an absolute or colon path, `:0`, a missing claim, a whitespace-only fragment are `malformed`), distinct counting toward `--require`, an uncommitted edit makes a pointer `stale`, an unusable `commit:` value is announced and fails `--strict`, the git child's environment carries none of `GIT_DIR` / `GIT_TRACE` / `GIT_EXTERNAL_DIFF` from the parent, a root of `/`, a usage error beating pointer failures, and a worst-case timing bound (2000 mismatching pointers into a 2 MiB target: under 2 s on a laptop where the scan-per-pointer version took 28 s; asserted under 15 s so a slow CI runner is not a false alarm). `test/rules*.test.mjs`: rendered coder and tester definitions contain the five headings; the rendered rules contain the two bullets. No test spawns a vendor binary; temp dirs cleaned in `after()`.

## Non-goals

No `omelette-scout` agent definition; no automatic map generation; no checking of the claim text; no change to the review flow, the guard, the write gates, the env allowlist or any tool schema; no config key.

## Flow

Checker → `omelette-coder`; tests → `/omelette-test`; template and doc text → the session (or a docs-class agent); three release reviews (Codex, Grok, Opus whole-branch) with the four-part finding format; Linux green on the pushed branch before the tag; atomic commits.
