## Why

The operating model is prose: a rules file the session reads on every request (14 590 characters, at its ceiling) and a guard script behind a settings hook. Claude Code now ships function hooks ("mods") as a plugin API: a module that the engine calls on tool calls, agent spawns, model steps, stops and compactions, with a display surface of its own. The operator asked two things on 2026-10-04: can the rules move onto deterministic mods, and can a mod show the orchestrator and the whole fleet at work — who is talking to whom right now.

The honest split of the rules is three ways: about a third are mechanical gates a mod can enforce, a third are things a mod can make visible, a third are judgement that stays prose (and can arrive by event instead of sitting in the rules file). This release ships the foundation every later slice stands on — the plugin folder, its delivery, the fleet model, the test split — and the first slice on it: **the pane**. The pane only reads. Nothing in 1.7.0 refuses, rewrites or blocks anything.

The API is early access (the declaration file says so in its header, and it grew from 13 186 lines at Claude Code 2.1.277 to 20 422 at 2.1.289). The mod is therefore an optional surface: the units, the CLI, the rules file and the guard hook work exactly as before with or without it.

## What the spike proved

A throwaway mod ran in the operator's session on Claude Code 2.1.289 (ledger, 2026-10-04). Each line is something the engine did, not something the types promise:

- A tool call inside a sub-agent's loop carries the loop's `agentId`, and `$.agent.list()` maps it to the agent type the project defines (`omelette-coder-medium`), with its status.
- `agent.spawn` reports the resolved model (`claude-opus-5-5`) and the new agent's id; `turn.step` reports model and effort per request per loop (`medium` for the coder, `high` for the main loop).
- `classic.SubagentStop` fires with `agent_id` and `agent_type` 0.8 s after a sub-agent's hand-back.
- `session.measure` pushes context fill, the rate-limit windows and the session's cost.
- `$.ui.open` placed a pane on the operator's terminal; a `ui.render` hook drew it and redrew it on every state write.
- `$.process.run` of `omelette-fleet check` took 63 ms and of the guard script 37 ms; the guard refused a coder's `git commit` with its own text. (Used by later releases, not this one.)
- A `classic.Stop` hook answering `{ block }` held the turn once. (Later releases.)
- A hooks module may import a plain `.mjs` file from its own folder (`claude plugin validate` accepted it).

## The pane

One pane, id `omelette-fleet`, three zones top to bottom.

**Header, one line.** Context fill and the five-hour and seven-day windows: `ctx 31% · 5h 11% · 7d 71%`. A figure the engine does not have is left out. (Amended 2026-10-08, operator: the session's cost is not shown — on a subscription it is the API price of the tokens, not a bill, and the windows already say what is spent.)

**The graph.** Boxes are actors, lines are who called whom. Three layers: sub-agents above, the orchestrator in the middle, the units below.

```
┌───────────────┐ ┌───────────────┐ ┌───────────────┐
│ ▶ coder-medium│ │ · tester      │ │ ▶ reviewer    │
│ opus · medium │ │ sonnet · high │ │ opus · xhigh  │
│ Bash: npm test│ │ reported 3:10 │ │ Read adapter… │
└───────┬───────┘ └───────┬───────┘ └───────┬───────┘
        └─────────────────┼─────────────────┘
             ┌────────────┴────────────┐
             │ ● orchestrator          │
             │ fable-5-1 · high · 31%  │
             └────────────┬────────────┘
        ┌─────────────────┼─────────────────┐
┌───────┴───────┐ ┌───────┴───────┐ ┌───────┴───────┐
│ · gemini      │ │ ▶ grok        │ │ · codex       │
│ idle 12m      │ │ code_review   │ │ idle          │
│               │ │ grok-4.7 2:17 │ │               │
└───────────────┘ └───────────────┘ └───────────────┘
```

- **A box** has three lines of fifteen cells: a state glyph and the role (the `omelette-` prefix dropped); model · effort (ids shortened: `claude-opus-5-5` → `opus`, `claude-fable-5-1` → `fable-5-1`; a unit shows its tool on line two and model with elapsed time on line three); what it is doing now (`Bash: npm test`, `Edit adapter.mjs`, `grok_code_review`) or its state with a duration (`waiting 3:10`, `reported 0:40`, `idle 12m`).
- **State glyphs**: `●` the orchestrator; `▶` running (a call or a model step in flight); `·` idle — a unit with no call, or a sub-agent that stopped and reported (`reported 3:10` is the time since its stop; a `SendMessage` that resumes it turns it back to `▶`); `◌` an agent the engine lists as `idle` without a stop — a teammate waiting for a message.
- **A live line** — the link between a running agent and the loop that spawned it, and between a caller and a unit whose call is in flight — is drawn in the accent colour and bold; every other line and every idle box is dim. Liveness is colour, never a different glyph (see [Surfaces and terminals](#surfaces-and-terminals)).
- **Who is the caller.** A unit called from a sub-agent's loop is marked in its box (`← coder-medium`) and in the history; the terminal draws no line across the orchestrator's row. The desktop drawing has the room and draws the real line.
- **How many boxes.** The three units are always there. Sub-agents: one row, as many boxes as the width holds (three at 53 cells, four at 71, up to six) — every running or waiting one first, then the most recently stopped; the rest fold into the row's last box, `+N more`. A layer never wraps: below 53 cells, where the three units no longer fit side by side, or when the pane is too short for the graph, the same actors are drawn as an indented tree, two lines each.

**History, as lines.** Under the graph, the newest links first, as many as the pane's height leaves (amended 2026-10-08: on a terminal pane that can be one row — the graph needs 20; the desktop shows at least three): `12:05:40 orchestrator → grok · code_review`, `12:04:52 coder-medium → orchestrator · report`, `12:04:10 orchestrator → coder-medium · Agent`. Kept for the session, the last 200.

**Opening it.** The command `/omelette-fleet` opens the pane at any width (`/omelette-fleet close` closes it). At session start the mod asks for the pane unasked, which the engine seats only on a wide terminal (144 columns, or 110 once the person has opened it); the `autoOpen` option (default `true`) turns that off. With the pane closed, one status-line entry says the same in short while anything is running: `fleet: coder-medium, grok 2:17`; nothing when all is idle.

**Motion.** (Added 2026-10-08, operator: running actors should be animated, so the eye finds them.) A running box's state glyph is a spinner (`⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏`, ASCII `|/-\`), and its frame is drawn in the accent colour and bold like a live line; an idle or reported box stays dim. The spinner's frame comes from the model's clock, so the drawing stays a pure function of the state. While anything runs the tick is 250 ms; when nothing runs it falls back to 1 s, so an idle session pays nothing extra. On the desktop the live lines run as a dashed stroke from caller to callee and a running box's frame pulses, both CSS animations inside the SVG, turned off under `prefers-reduced-motion`. The `animate` option (boolean, default `true`, a row in Claude Code's config menu) turns all motion off — the accent frames stay.

**Language.** The pane's strings are English, like the package.

## Data sources

| On screen | Comes from |
|---|---|
| A sub-agent appears, with its role and parent | `agent.spawn` (`subagentType`, result `agentId`, the spawning loop's `agentId`); after a hot reload or a resume, `$.agent.list()` |
| Its model and effort | `agent.spawn`'s result (`model`), then `turn.step` for that `agentId` (`model`, `effort`) |
| The orchestrator's model and effort | `turn.step` on the main loop |
| What an actor is doing | `tool.call` in its loop: the tool and a short subject (a Bash command's first words, a file's base name, an MCP tool's name); cleared when the call returns |
| Running, waiting, reported | `$.agent.list()`'s `status` at each event of that agent; `classic.SubagentStop` marks `reported` with its time; the next `turn.step` of that agent marks it running again |
| A link in the history | `tool.call` on `Agent`, `SendMessage`, a hand-back, and any `mcp__<server>__<unit>_<tool>` |
| A unit's call from this session | the `tool.call` to its MCP tool, from the loop that made it, from the call's start to its return |
| A unit's model, effort, start time, and calls made by other sessions | the status feed: `status-<unit>-<pid>.json` (schema 2) under the fleet home (`$OMELETTE_HOME`, default `~/.omelette`), read while the pane is open; a call no loop of this session made is shown as `other session` |
| Header figures | `session.measure` and `$.session.usage()` |

The unit names are the package's three (`gemini`, `grok`, `codex`), matched on the tool part of the MCP name, so the operator's server prefix (`orion-…`) does not matter. A test compares the mod's list with the package's `units/` directory.

## Architecture

```
mods/omelette-fleet/
  .claude-plugin/plugin.json   name, version (= the package's), description, types, userConfig { autoOpen }
  hooks/hooks.json             { "modules": ["./register.tsx"] }
  hooks/register.tsx           the only file with `$` calls and JSX: hooks → model → draw
  hooks/model.mjs              pure: (state, event) → state — nodes, links, history
  hooks/feed.mjs               pure: status snapshots (schema 2) → unit nodes
  hooks/layout.mjs             pure: (state, width, height) → rows of styled segments; and node/link coordinates
  hooks/svg.mjs                pure: (state) → an SVG document and its alt text
  hooks/text.mjs               pure: cut, durations, short model names, subjects
  types/index.d.ts             the `$.state` contract
  tests/*.test.ts              `claude plugin test` (needs Claude Code; run at the live gate)
.claude-plugin/marketplace.json  the package root as a folder marketplace
test/mod-*.test.mjs              `node --test` over the pure files (CI)
```

- **The split is the point.** Everything that decides what is on screen is a pure function in a `.mjs` file with JSDoc types and no import but its neighbours — so `npm test` runs it on Node 20 and 22 without Claude Code, as CI requires. `register.tsx` is thin: each hook turns the engine's event into a model event, writes the state, and returns `next(e)` untouched; the render hook reads the state and maps layout rows to `Text` elements (or the SVG to one `Svg`).
- **State lives in `$.state`** (one value, `omelette-fleet.fleet`), declared in the contract, so a hot reload and a redraw both start from it. Module variables hold timers only.
- **Time.** One `$.clock.every` tick per second while the pane is open (durations, and a re-read of the status snapshots); stopped on `ui.close`. Nothing ticks while the pane is closed; the status-line entry updates on events.
- **Zero dependencies holds.** The engine compiles the TypeScript; the package gains no build step and no install.
- **The engine scans the module's source** for `$.noun.method` written literally and refuses what it did not see, so `$` is never aliased or passed under another name.

## Surfaces and terminals

- **Terminal.** The graph is text: one set of light box-drawing characters (`┌ ─ ┐ │ └ ┘ ┬ ┴ ┼`) and four state glyphs, all single-cell in iTerm2, Terminal.app, Ghostty, kitty, the VS Code terminal and under tmux. Heavy and mixed-weight junctions are not used: fonts differ on them. Live is colour plus bold; dim is `dimColor`.
- **No colour.** With `NO_COLOR` set or `TERM=dumb`, live links are marked by the `▶` on the box alone and the frame falls back to ASCII (`+ - |`).
- **Width.** The layout is computed from the pane's `bodyColumns`, never the terminal's; it re-runs when the width changes. From 53 cells it is the graph; below that, the tree. Every string is cut by cells with an ellipsis; the mod writes no wide (two-cell) characters of its own, and a role or tool name containing one is cut by code points on the safe side.
- **Desktop, VS Code, mobile.** The same model is drawn as one `Svg` (boxes, real lines including agent-to-unit, the live ones in the accent colour) with an `alt` that reads the graph as text, followed by the history as text lines.
- **The pane as a sidebar or inline** is the engine's decision (`viewport.isFullscreen`); the mod draws the same tree in both.

## Delivery

The CLI never writes Claude Code's settings and does not here. `omelette-fleet rules --mods` prints what to run and why:

```
claude plugin marketplace add <the package root>
claude plugin install omelette-fleet@omelette-fleet
```

A marketplace that is a folder is read in place, so an updated package is an updated mod after `/reload-plugins`. For a look without installing, the same output names the one-session form, `claude --plugin-dir <the package root>/mods/omelette-fleet`. `package.json` ships `mods` and `.claude-plugin`. The plugin's version equals the package's (a test pins it).

Task 1 proves this path on a real machine before anything is built on it; if a folder marketplace does not behave as the plugin reference says, the fallback is `--plugin-dir` / `CLAUDE_CODE_PLUGIN_DIRS` (a printed snippet), and the spec is amended before Task 2.

## Failure behaviour

- A hook of the mod that throws or overruns its budget is skipped by the engine and the event proceeds; every hook here returns `next(e)` unchanged, so a broken mod costs the pane and nothing else.
- No fleet home, an unreadable or malformed snapshot, a schema other than 2: the unit's box says `no feed`; the call links of this session still show, since they come from `tool.call`.
- A snapshot whose process is gone (a stale `active[]`): the mod spawns nothing, so it cannot ask about a pid; a snapshot with a call in `active[]` and an `updatedAt` older than 2 hours reads as idle. (Amended 2026-10-08: the first text said 30 minutes, "past the units' 20-minute ceiling"; no such ceiling exists — `timeoutS` runs up to a day, the feed has no heartbeat, and a default deep research takes about 36 minutes.)
- An agent the engine lists but the mod never saw spawn (a reload, a resume): taken from `$.agent.list()` with what it has (type, status, parent); model and effort appear at its next step.
- A Claude Code build whose event shapes differ: the hooks fail and are skipped; `docs/MODS.md` names the tested build, and the live gate re-tests on the build of the day.
- More than one session: each session's mod has its own state; units called by another session show as `← other` (amended 2026-10-08: `other session` does not fit a 14-cell box line).

## Out of scope and the road after

Not in 1.7.0: anything that refuses, rewrites or blocks; the guard's refusal logic (frozen, untouched); the settings hooks; the rules file's text; the Omelette menu-bar app (it keeps reading the same feed).

The slices that follow, each with its own spec, in this order:

1. **Guard v2 and the handoff veto.** `tool.call` asks the existing guard script (the mod is delivery, the script stays the logic and its test table stays the test); `agent.spawn` pins the roles' models; `session.compact` is skipped until the ledger has a fresh `## Handoff`. The classic hook stays as the fallback delivery.
2. **The gates.** Tester-after-coder at the commit and at the stop; the release commit's checks (a fresh green suite, a dated CHANGELOG, no home paths); the small-change lane's twenty lines; reports checked by `omelette-fleet check` as they are written. The pane gains a gates line.
3. **Rules by event.** The judgement rules handed to the model when they apply (`additionalContext` on a sub-agent's stop, a context block after a compaction), and the rules file shrinking under its ceiling by what moved.
4. **Cost per task and role**, from `session.measure`, as ledger lines; `/omelette-test` as a mod command that takes the diff itself.

## Verification
