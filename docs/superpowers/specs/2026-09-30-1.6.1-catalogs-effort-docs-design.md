## Why

Three things moved under the package in one week, none of them in its code: OpenAI shipped the GPT-6 Sol and Luna tiers (Codex CLI 0.157.0, 2026-09-25) and GPT-6.1 Sol as the CLI's new bundled default (0.159.1, 2026-09-29); Anthropic shipped Claude Sonnet 5.5 (2026-09-28), which the `sonnet` alias already resolves to, with effort guidance that contradicts the shipped tester's `xhigh`; and the operator, re-reading the docs, found ORCHESTRATION current against the code (the 2026-09-26 audit) but stale against the practice — the tester dispatch, the Codex lineup, the missing effort policy — and unreadable where a paragraph runs to 1 500 words.

## Tasks

**T1 — the Codex catalog.** `units/codex/models.js` lists the GPT-6 generation: `gpt-6.1-sol` becomes the fleet default at effort xhigh (operator ruling 2026-09-30: near-Astra quality at a fifth of the price), `gpt-6-astra` stays for the heavy reviews only (the pre-release security audit, root-cause hunts), `gpt-6-sol` is the regression fallback, `gpt-6-luna` the cheap tier; the 5.6 tiers stay, marked superseded — verified at the task: OpenAI's deprecation schedule names them only as substitutes and Codex's own catalog carries no retirement date for them (a research pass had claimed a 2026-12-11 shutdown; rejected). The unit's built-in effort moves to xhigh with the default, and the effort allowlist follows what `codex debug models` lists for the GPT-6 generation: `ultra` in (probed), `none` out. Every number lands the way Grok 4.7's did: vendor figures labelled vendor, Artificial Analysis figures read by curl, dates on each. `gpt-6.1-sol` carries the rollout note (rejected on a ChatGPT account by codex-cli 0.157.1 on 2026-09-30; the live gate re-probes on the operator's updated CLI). `doctor` gains a `models` line for codex like grok's: the CLI's bundled default beside the catalog, since 0.159.1 changed it under the fleet's feet. Docs that name the lineup follow: ORCHESTRATION's Codex escalation block and routing rows, README, GUIDE strings, CHANGELOG.

**T2 — the effort policy.** The tester's default effort becomes `high` (`agents.tester.effort`, CONFIG, the rendered definition), on Anthropic's Sonnet 5.5 guidance — `xhigh`/`max` reserved for a measured gain, and at those levels the model "can start its own rounds of review… make related fixes it noticed along the way", the one thing a tester must not do. The coder and tester templates gain the stop-and-report paragraph (done and checked → stop; no unasked tests, files, docs, refactors or review rounds; say so at the end instead). ORCHESTRATION gains a section "Effort by role and model": which role runs on which alias, what each alias resolves to today (Opus 5.5, Sonnet 5.5; Claude Code ≥ 2.1.284), the measured Opus rule (medium = xhigh on a plan-driven task), the Sonnet 5.5 rule, and that the values are config. One matched pair inside the release — the tester at `high` and at `xhigh` on one task's diff — goes to MEASUREMENTS; the default holds unless the pair says otherwise.
