# 1.0.0 — the docs become maps, the pictures that beat prose, and the Windows line

**Status:** shape approved in chat by the operator 2026-09-11; this spec awaits review · **Base:** main `d44bfbe` (v0.3.7) · **Branch:** `feat/1.0.0`

## Why

The backlog's S and M columns closed in 0.3.6 and 0.3.7; L1 (native Windows) is deferred past 1.0 by the operator's decision. What remains for 1.0 is not a feature: the docs are prose a reader has to read end to end, README does not map the set, and the repository still runs a Windows CI job it calls a signal. 1.0.0 fixes the reading experience and says plainly what is supported.

No behaviour changes. No new tools, keys or hooks.

## 1. Every doc opens with a map

- **Rule.** Each of README, `docs/ORCHESTRATION.md`, `docs/CONFIG.md`, `docs/SECURITY.md`, `docs/ADAPTERS.md`, `docs/STATUS-FEED.md`, `docs/ARCHITECTURE.md` gets a **map block** directly after its title and one-line summary: a table `| Question | Where |` with one row per top-level section (and per sub-section where the sub-section answers its own question, e.g. CONFIG's `results --stats`). The question is the reader's, in their words ("Which keys exist and what do they default to?"); the Where cell is a link to the section's anchor in the same file (`[Keys](#keys)`).
- Section text is not rewritten. The map is added; wording inside sections changes only where a sentence is now false (the Windows line, see §3) or where a diagram replaces a paragraph that only described a picture (§2).
- **README is the map of the set.** A `## Documentation` section near the top holds a table `| If you want to know… | Read |` with one row per doc (the seven above plus CHANGELOG), each row a question the doc answers. README's own map follows the same `| Question | Where |` shape.
- **Anchors follow GitHub's slug rule**: lowercase, spaces to `-`, punctuation dropped, backticks dropped. The test in §5 checks them.

## 2. Diagrams where a picture beats prose

Drawn with the `diagram-design` skill (cathrynlavery/diagram-design, MIT; version 2.6 cloned into the session's scratchpad for the drawing agent's reference — not installed as a plugin, nothing of it is vendored into this repository). Six diagrams, one per place where the current text describes a shape:

| # | Doc · section | Type | What it shows |
|---|---|---|---|
| D1 | README · How it fits together | Architecture | The Claude Code session (focal), the three MCP servers, the vendor CLIs they spawn, the fleet home (`fleet.config.json`, status feed, result spool). One direction of trust: units propose, the session applies. |
| D2 | ARCHITECTURE · The path of one call | Sequence | Tool call → unit runtime → config resolution → spawn (env allowlist, caps) → CLI → status feed + spool → response, with the cancel/timeout branch. |
| D3 | ORCHESTRATION · The operating model | Swimlane | Lanes: operator, session, `omelette-coder`, `omelette-tester`, fleet units. Plan → spec approved → code → test with the diff → arbitration → reviews → session commits and merges. Who never commits is visible from the lanes. |
| D4 | ORCHESTRATION · Ledger and handoff | State machine | The context-fill lifecycle: below threshold → nudged (PostToolUse) → Stop gated once → handoff written → compaction (PreCompact stamp, PostCompact summary) → SessionStart prints the last handoff. |
| D5 | SECURITY · The ceiling | Layer stack (compensating security layers pattern) | Config ceiling (`OMELETTE_ALLOW_WRITE`) → env allowlist + billing scrub → per-unit sandbox (Codex kernel, Grok layers, Gemini policy) → guard hook, each labelled with how strong it is and what it does not cover. |
| D6 | CONFIG · Resolution order | Flowchart | Per-key resolution: env override → `fleet.config.json` (unit block, then top level) → adapter builtin → schema default, and where the ceiling narrows the result. |

- **Files.** `docs/assets/diagrams/<name>.html` (the skill's self-contained source, kept so a diagram can be edited) and `docs/assets/diagrams/<name>.svg` (the export the docs embed). Names: `fleet-topology`, `call-path`, `operating-model`, `handoff-lifecycle`, `security-layers`, `config-resolution`.
- **Embedding.** `<img src="docs/assets/diagrams/<name>.svg" alt="…" width="…">` (README) / `../assets/diagrams/…` (docs/). Alt text says what the diagram shows in one sentence, so the map row and a screen reader both work.
- **Export rules** (recorded as rulings in the ledger): SVG only, no PNG; the skill's Google-Fonts `@import` is **not** injected — GitHub serves README images through a proxy that loads no external resource — the text uses a font stack with system fallbacks; one light variant with an opaque paper background so it reads as a card under both GitHub themes; the export normalises `rgba()` to hex + opacity as the skill's export procedure says, so strict SVG readers render it.
- **Style tokens** from the logo: `ink` `#012357`, `paper` `#f3f3f1`, `accent` `#fac440`; the skill's other roles derived from those per its style guide. Accent on at most two focal nodes per diagram, as the skill insists.
- **Where the text changes.** A paragraph that only narrated the picture (README's "How it fits together" opening, ARCHITECTURE's "path of one call" list if the sequence carries it) shrinks to one lead sentence plus the diagram; every fact the paragraph carried must survive somewhere on the page — in the diagram's labels or in the remaining text. The drawing agent reports which sentences it dropped; the session checks each.

## 3. Windows: the line

README "Requirements": *macOS or Linux. Native Windows is not supported yet — the package runs on Windows through WSL; a native harness (`.cmd` shims for the vendor CLIs, path and file-mode differences) is planned after 1.0. CI does not run on Windows.* The "43 tests fail" sentence goes; the hook-snippet paragraphs that describe Windows quoting stay (they are true and describe the printed snippet).

## 4. CI matrix without Windows

`.github/workflows/test.yml`: `os: [ubuntu-latest, macos-latest]`, Node 20 and 22; the `continue-on-error` line and the "SIGNAL, not a gate" comment go; the header comment says the matrix is the two supported platforms. Nothing else in the job changes.

## 5. The one test: `test/docs-map.test.mjs`

- Each of the seven docs contains a map table (a line matching `| Question | Where |` or, in README's documentation section, `| If you want to know… | Read |`) within the first 60 lines of the file (README opens with an HTML header, so the window counts from line 1).
- Every intra-file link in a map (`[…](#anchor)`) resolves to a heading in that file under GitHub's slug rule (implemented in the test in a dozen lines: lowercase, strip everything but letters, digits, spaces and hyphens, spaces to hyphens; duplicate headings get `-1`, `-2`).
- Every cross-file link in README's documentation table resolves to an existing file.
- Every `docs/assets/diagrams/*.svg` referenced from a doc exists, opens with `<?xml`, carries `xmlns="http://www.w3.org/2000/svg"` and a `viewBox`, and contains no `@import`; every `.svg` in that directory is referenced from at least one doc.

## 7. Who does what, and the commits

- **Maps (§1) and the Windows line (§3):** one Sonnet-class docs agent, one brief for all seven files. The session checks every question against the section it points at.
- **Diagrams (§2):** one Opus-class agent per drawing round with the skill's `SKILL.md`, the six type references, `style-guide.md` and `export.md` in its brief; it writes the six `.html` + `.svg` pairs and the embed lines, and lists the sentences it removed. Taste is reviewed by the session with the rendered SVGs open.
- **Test (§5), CI (§4), bump and CHANGELOG (§6):** the session, under the small-change exception (each is a short, behaviour-free edit with its check in the same commit).
- **Commits, atomic:** one per doc for the maps (7), one for README's Windows line, one per diagram with its embed (6), one for the CI matrix, one for the test, one for the bump + CHANGELOG. About 17.

## Non-goals

- No section is rewritten for style; no doc is split or merged; the rules template is not touched (it is a managed file, not a doc, and its text was settled in 0.3.6–0.3.7).
- No dark-mode diagram variants, no PNGs, no diagram in STATUS-FEED or ADAPTERS (their tables already are the picture).
- No native Windows work; no CI on Windows even as a signal.
