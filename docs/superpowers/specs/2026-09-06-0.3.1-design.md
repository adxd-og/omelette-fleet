# 0.3.1 — ledger and handoff, mechanical tester handoff, Grok streaming salvage

**Status:** approved by the operator 2026-09-06 (with the dynamic maxTurns amendment) · **Base:** main `e24951d` (v0.3.0)

## Why

0.3.0 shipped the operating model as text. 0.3.1 turns three of its rules into mechanisms and fixes one thing 0.3.0 promised but cannot deliver for Grok.

## Verified facts this design rests on (2026-09-06)

- Grok CLI `--output-format json` writes NOTHING until the run ends (0 bytes at 20 s on a run that had produced text in plain mode by 16 s), so 0.3.0's hard-kill salvage never has anything to salvage for `grok_research` / `grok_code_review`. `--output-format streaming-messages-json --include-partial-messages` emits NDJSON in the Anthropic Messages wire format: one `system/init` line, then `stream_event` lines (`message_start`, `content_block_start`, `content_block_delta` with `delta.type: text_delta`/`thinking_delta`, `content_block_stop`, …), then whole messages; 441 text deltas / 1513 chars assembled at the 30 s kill of a probe.
- Claude Code: agent definitions in `.claude/agents/` are hot-reloaded within seconds except when the directory did not exist at session start; `disallowedTools` is enforced (the shipped `omelette-coder` shows "All tools except Agent" in the session); effort precedence env > definition > session.
- SPIKES DONE 2026-09-06 (Claude Code 2.1.261, `claude -p`, scratch project): (a) a skill with `context: fork`, `agent: <custom>`, `disable-model-invocation: true` and a body containing !`git diff HEAD` hands the forked agent the diff and `$ARGUMENTS` (probe answered `DIFF_SEEN: yes / ARGS: SPEC.md`); docs: !`cmd` runs at render time, before the fork, and a failing command aborts the invocation; skills hot-reload except a top-level skills dir created after session start. (b) A `hooks:` block in an AGENT definition's frontmatter did NOT fire at all (no log line, `git commit` went through), contrary to the docs; a project `settings.json` `PreToolUse` hook with `matcher: Bash` DID fire for the same subagent, blocked with exit 2, and its stdin JSON carried `agent_type: spike-coder` (and no `agent_type` for the main thread) → the coder guard is a settings-level hook keyed on `agent_type`, not a frontmatter hook. (c) `PreCompact` fires on a manual `/compact` (stdin `trigger: "manual"`) even when there is "Not enough messages to compact"; the hook's append to `ledger.md` landed; whether its stdout reaches the post-compaction context could not be observed in print mode; the design does not depend on it.
- Verified before the spikes: (a) skill frontmatter `context: fork`, `agent:`, `disable-model-invocation`, `argument-hint`, and `!`cmd`` injection at invocation; (b) `hooks:` in an agent definition's frontmatter firing `PreToolUse` and blocking with exit 2; (c) `PreCompact` hook: is it fired before auto-compaction, and does its stdout / `additionalContext` reach the post-compaction context.

## 1. Grok streaming output (units/grok/adapter.mjs)

- Research/review runs switch to `--output-format streaming-messages-json --include-partial-messages`. Image runs unchanged.
- One parser for both paths: assemble the answer from `text_delta` events (ignore `thinking_delta`), prefer the final whole `assistant` message's text when present (it is the authoritative full text), take `stop_reason` and `usage` from the final message / `message_delta` when present. Partial markers as in 0.3.0: `[grok: run ended early — stopReason=…]`, `[grok: CLI exited N — …]`, `[grok: hard-killed after Ns — …]` — the last one now carries the deltas assembled so far.
- Usage: if the final message carries `usage`, report it in the status feed (Grok reported none before).
- Tests: fixture NDJSON streams (complete run; killed mid-delta; a run with tool-use blocks between text blocks; a run whose final message text differs from the deltas → final wins), plus the existing plain-mode tests for image tools. Fake-binary CLI test for `grok_research` returning the assembled text.
- Docs: ORCHESTRATION "Supervising", STATUS-FEED (Grok usage now present), ADAPTERS (streaming as the recommended shape), CHANGELOG.

## 2. Ledger and handoff (operating model → mechanism)

- **Rule** (rules file + ORCHESTRATION, new section "Ledger and handoff"): the orchestrator keeps a ledger file for every plan from the first step — one line per event, every decision as `Ruling: <what> — <why> — <cost if wrong>`, tasks marked complete with their commits. Before a compaction (announced or suspected), and at every natural pause, it appends a **handoff block**: where the work stands, open findings, agents in flight, next action. After a compaction it re-reads the ledger before doing anything else. Location: `<project>/.omelette/ledger-<plan>.md` (recommended `.gitignore` entry `.omelette/`), or wherever the project's own convention puts it — the rule is the file, not the path.
- **Hook**: `omelette-fleet rules --hooks` writes a managed `.claude/hooks/omelette-precompact.mjs` (marker as a `//` comment on line 1) and PRINTS the `hooks.PreCompact` snippet for `.claude/settings.json` — the CLI never edits settings.json (spec 0.3.0: Claude Code's config is read, never written). The hook appends `## Compaction <ISO ts> — re-read this ledger before continuing` to every `.omelette/ledger-*.md` in the project and, if the harness passes hook stdout into context, prints the last handoff block. Exact behaviour fixed after spike (c).
- Managed-file kinds generalise: rules, agents, hooks (and skills, §3) share `syncManagedFile`; `doctor` shows `hooks: v0.3.1 (1)`, `update` hints for stale ones, `--remove --hooks` removes only marked files.

## 3. Mechanical tester handoff: `/omelette-test`

- `omelette-fleet rules --agents` additionally writes `.claude/skills/omelette-test/SKILL.md` (managed, marker as an HTML comment right after the frontmatter): frontmatter `name: omelette-test`, `description`, `context: fork`, `agent: omelette-tester`, `argument-hint: [spec path]` — NOT `disable-model-invocation` (live check 2026-09-06: with it set, the Skill tool refuses the call and only a human can run `/omelette-test`; the orchestrator must be able to invoke it); body: "Spec: read $ARGUMENTS. Diff, taken from git at invocation:\n!`git diff HEAD`\nUntracked files:\n!`git ls-files --others --exclude-standard`" followed by the tester procedure. The diff is injected at invocation, so the tester cannot receive the coder's summary.
- Rules file "Tester flow" step 2: "Invoke `/omelette-test <spec path>`; the diff is injected at invocation." Falls back to the plain `subagent_type: omelette-tester` dispatch where skills are unavailable.
- Frontmatter confirmed by spike (a): `context: fork`, `agent: omelette-tester`, `disable-model-invocation: true`, `argument-hint: [spec path]`.

## 4. Agent hardening

- **Agent settings live in the fleet config; templates render from it.** New top-level `agents` block in `fleet.config.json` (validated like `SETTINGS_SCHEMA`): `agents.coder.model` (default `opus`), `agents.coder.effort` (`xhigh`), `agents.tester.model` (`sonnet`), `agents.tester.effort` (`xhigh`), `agents.tester.maxTurns` (`80`, positive integer). `renderAgentFile(name, version, settings)` substitutes `{{model}}`, `{{effort}}`, `{{maxTurns}}`; `omelette-fleet set agents.tester.maxTurns=120` accepts the dotted path; `show` lists the block; `rules --agents` re-renders and refreshes (the marker stays the ownership proof; a value change makes the content differ → "written … (v0.3.1, was 0.3.1)"). **Dynamic adjustment (operator request 2026-09-06):** the rules file says: "If the tester reports a turn-limit truncation, raise it and re-run: `omelette-fleet set agents.tester.maxTurns=<n> && omelette-fleet rules --agents` — the session picks the new definition up within seconds; then re-dispatch the tester." The orchestrator may do this on its own; it is a config change, not a code change.
- `omelette-tester`: `maxTurns: {{maxTurns}}` (default 80); body: "If you hit the turn limit, say so in the report — a truncated run is not a failing suite; the orchestrator can raise `agents.tester.maxTurns` and re-run you."
- `omelette-coder` guard (spike (b): frontmatter hooks do not fire; settings-level hooks do and see `agent_type`): `rules --hooks` writes ONE managed script `.claude/hooks/omelette-guard.mjs` serving both events. `PreToolUse` (matcher `Bash`): when stdin `agent_type` is `omelette-coder` and the command matches `\bgit\s+(commit|push|stash|checkout\s+-b|switch\s+-c|worktree)\b`, exit 2 with "omelette-coder never commits, pushes, stashes, branches or opens worktrees; report instead". `PreCompact`: append the ledger marker (§2). The CLI prints the settings.json snippet wiring both events; `doctor` reads settings.json (read-only) and reports `hooks: v0.3.1 (1) · wired: PreToolUse, PreCompact` or `not wired: paste the snippet from rules --hooks`. Superseded text: `.claude/hooks/omelette-no-commit.mjs` that exits 2 with "omelette-coder never commits, pushes, stashes, branches or opens worktrees — report instead" when the command matches `\bgit\s+(commit|push|stash|checkout\s+-b|switch\s+-c|worktree)\b`. Fixed after spike (b); if agent-frontmatter hooks do not fire on 2.1.x, the script still ships and `rules --hooks` prints the settings.json snippet for a project-wide `PreToolUse` guard keyed on the agent name (or the item is dropped with a ledger ruling).
- Both templates: "Never `git stash`…" line already in the coder (0.3.0); the tester gets "Never modify the implementation or the implementer's tests."
